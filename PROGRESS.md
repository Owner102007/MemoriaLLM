# PROGRESS.md — состояние проекта «Memoria LLM HB»

*Обновляется в конце каждой сессии. Читается в начале каждой сессии вместе с `CLAUDE.md`.*

**Текущая сессия: S5.1 завершена (23.08.2026) — книга больше не копируется в приложение и открывается любого размера. Следующая: S5.2 — библиотека и обложки; к её началу пригодится описание формата каталога «Библиотеки ХохлоБарона».**

**Прежде чем сообщать «не работает», стоит сверить строку сборки на экране настроек с последним тегом.** В S4.5 это уже стоило целой итерации: правки лежали в `main` невыпущенными, а владелец проверял прошлый тег.

### Что изменилось после перехода в open source

**CI перестал быть узким местом.** Публичный репозиторий получает безлимитные минуты GitHub Actions, включая Windows-раннеры, — двухуровневая экономная схема отменена, обе платформы собираются на каждый push.

**Отказ от Google Play Services.** Вход через Google делается браузерным потоком OAuth с PKCE, одинаково на Android и Windows. Это условие попадания в F-Droid, работа на телефонах без сервисов Google и один код OAuth вместо двух платформенных. Пакет `google_sign_in` из плана вычеркнут.

**Защита прокси при открытом коде.** Ключ провайдера LLM живёт в секретах Cloudflare, официальные сборки получают отзываемый токен доступа к прокси из GitHub Secrets через `--dart-define`. Плюс режим «свой API-ключ» для энтузиастов — уместен именно в открытом проекте и снимает нагрузку с общего прокси. Проверки Play Integrity не будет (она требует Play); её заменяют лимит на устройство в Workers KV и жёсткий дневной потолок.

**Лицензия GPL-3.0** — форки остаются открытыми, с MIT-лицензией pdfrx совместимо. Сменить на MIT легко, пока автор один, и почти невозможно после появления сторонних контрибьюторов: если нужна MIT — сказать до конца S1.

### Новое в плане: комфорт чтения (сессия S4)

Добавлена отдельная сессия **S4 «Читательская рамка»** — и это, по сути, главная функция продукта, а не полировка:

**Страница во весь экран.** Автоматическая обрезка белых полей (по координатам текстового слоя, для сканов — попиксельно), опция «игнорировать колонтитулы», ручная правка рамки с применением ко всей книге. Обрезанная область рендерится **в разрешении экрана**, а не растягивается из готовой картинки, иначе мелкий шрифт мылится.

**Режимы отображения:** страница целиком / половина страницы / разворот из двух страниц, плюс бесплатно получающаяся треть. Для двухколоночных PDF деление идёт по колонкам, а не по горизонтали. Режим запоминается для каждой книги и для каждой ориентации экрана. Смысл режима половины: кегль вырастает вдвое **без изменения вёрстки** — то, чего не может ни бумага, ни переформатируемый текст.

**Светофильтры** шейдером поверх страницы: ночной красный монохром с регулировкой, тёплый (снижение синего), сепия, инверсия с двойной инверсией картинок (иначе фотографии станут негативами), затемнение ниже системного минимума яркости, контраст и гамма для бледных сканов.

**Тема по умолчанию — тёмно-красная** (фон `#0E0708`, акцент `#A32F35`, текст `#E8DCD8`), вводится сразу в S1, чтобы весь UI строился в правильной палитре. Контраст каждой темы проверяется автотестом на WCAG AA: тёмно-красные схемы очень легко сделать красивыми и нечитаемыми.

Из-за вставки S4 сессии сдвинулись: библиотека теперь S5, выделение текста S6, Worker S7, облачная LLM S8, локальная LLM S9, CRDT S10, синхронизация S11, полировка S12, релиз S13.

### S1 — Каркас, открытая обвязка, CI (04.08.2026)

**Приложение.** Каркас Flutter со слоями `ui / application / domain / infrastructure`
и строгим `analysis_options.yaml` (`flutter analyze --fatal-infos --fatal-warnings`,
проверка `dart format` в CI). Навигация-заглушка: «Библиотека» и «Настройки».

**Темы.** Пять палитр, тёмно-красная по умолчанию. Цвета живут в `domain`
целыми числами ARGB — доменный слой не зависит от Flutter, перевод в `Color`
происходит на границе интерфейса в `ui/theme/theme_builder.dart`. Благодаря
этому контраст проверяется обычным юнит-тестом.

Контраст (WCAG 2.1) для каждой темы: основной и вторичный текст на фоне и на
поверхности — не ниже 4.5:1, подпись на акцентной заливке — не ниже 4.5:1,
нажатый акцент — не ниже 3.0:1. Худшее значение по всем темам — 4.74:1
(акцентный текст на поверхности тёмно-красной темы).

Опорный акцент `#A32F35` даёт к фону только 2.86:1, поэтому в палитре он
отвечает **только за заливку**, а для акцентного текста и иконок введён
отдельный, более светлый `accentText` (`#D2565B` в тёмно-красной теме).
Так фирменный цвет сохранён без потери читаемости.

**Обвязка.** README (миссия, приватность, сборка из исходников, структура),
CONTRIBUTING, CODE_OF_CONDUCT (Contributor Covenant 2.1), шаблоны issue
и PR, `.gitignore` с секретами и ключами подписи.

**CI.** `ci.yml` на каждый push: форматирование → анализ → тесты → APK
(ubuntu) → Windows и MSIX (windows-раннер), артефакты выкладываются.
`release.yml` по тегу `v*` собирает APK, AAB, портативный ZIP и MSIX
и создаёт черновик GitHub Release.

**Альфа-релиз.** Тег `v0.1.0-alpha.1` — первая сборка, которую можно
поставить руками: https://github.com/Owner102007/MemoriaLLM/releases/tag/v0.1.0-alpha.1

Артефакты прогона CI качаются **только с входом в аккаунт** и приходят
ZIP-архивом — на телефон так не поставить. Релизные ассеты качаются прямой
ссылкой без авторизации, поэтому `release.yml` публикует релиз сразу, а не
черновиком; тег с дефисом уходит предварительным релизом. В релиз кладутся
только APK и портативный ZIP: AAB нужен магазинам, MSIX подписан
заглушечными данными Partner Center — оба остаются артефактами прогона.

APK весит 42 МБ, потому что несёт все ABI сразу. Уменьшается через
`--split-per-abi`; отложено до S13, чтобы не плодить файлы до появления
настоящей подписи.

### Решения и находки S1

**У сессии нет Flutter SDK.** Сеть контейнера пропускает только `github.com`,
npm и PyPI; `storage.googleapis.com` (SDK и Dart) и `pub.dev` закрыты.
Поэтому анализ, тесты и сборки идут **только через CI** — это не временное
неудобство, а рабочая схема на весь проект. Соответствующий раздел
`CLAUDE.md` обновлён.

**Платформенные папки сгенерированы на раннере.** `android/` и `windows/`
создал workflow `bootstrap.yml` командой `flutter create` и закоммитил
в репозиторий; после этого он снят с триггера push и остаётся только
на ручной запуск. Писать эти папки руками было бы дорого и ненадёжно.

**Внутренние документы не публикуются.** Решение владельца от 04.08.2026:
`dev_plan_sessions.md`, `strategy_pdf_reader.md` и `SETUP.md` остаются
в папке `docs/` рядом с репозиторием. В SETUP.md есть незаполненные поля
под адреса и идентификаторы аккаунтов — именно в такой файл однажды
случайно впишут лишнее.

**Выбор темы пока не сохраняется** между запусками: слой данных появляется
в S2, тогда же тема переедет в настройки на диске.

**Читать результаты CI из сессии больно.** Логи прогона GitHub отдаёт
только авторизованным, а `api.github.com` закрыт прокси контейнера. Сводка
прогона (`$GITHUB_STEP_SUMMARY`) тоже видна лишь авторизованным — проверено.
Работают **аннотации**: их видно анонимно на странице прогона. Поэтому CI
при падении дублирует хвост вывода форматирования, анализа и тестов
аннотацией `::error::`, а полную сводку пишет для владельца.

**`dart format` и `require_trailing_commas` конфликтуют.** Форматер
переносит длинный вызов на новую строку, не добавляя хвостовую запятую,
а линтер при `--fatal-infos` считает это ошибкой. Лечится многострочной
формой вызова с запятой — она устойчива к обоим.

**Заглушки для Microsoft Store.** `identity_name` и `publisher` в
`msix_config` — временные значения до регистрации в Partner Center (S13).

### S2 — Слой данных на drift/SQLite (07.08.2026)

**Схема.** Восемь таблиц: `books`, `reading_progress`, `book_settings`,
`quotes`, `notes`, `bookmarks`, `llm_queries`, `app_settings`. Первые семь
несут поля CRDT — `hlc`, `node_id`, `modified`, `is_deleted` — с именами,
которых ждёт `sqlite_crdt`: S10 добавит движок слияния, а не станет
переписывать таблицы с данными живых читателей.

Настройки чтения хранятся **на книгу и на ориентацию экрана** (составной
ключ `book_id + orientation`): режим отображения, автообрезка, ручная
рамка, светофильтр, яркость, контраст, гамма — всё, что понадобится S4.
Позиция чтения — страница, фрагмент, смещение и доля прочитанного:
смена режима или устройства не должна сбивать место.

**История LLM — она же кэш.** `llm_queries` хранит выделение, контекст,
задачу и ответ; повторное выделение того же слова в том же абзаце
находится в базе и не стоит ни запроса в сеть, ни нагрева телефона.

**Удаление — надгробие, а не `DELETE`.** Иначе удаление на телефоне
никогда не доедет до ПК. Физическая чистка вынесена в `purgeDeleted()`,
внешние ключи с каскадом и `PRAGMA foreign_keys = ON` уносят вместе
с книгой её цитаты, заметки и закладки.

**Метки HLC проставляются с первой записи.** Гибридные логические часы
живут в `domain/sync/hlc.dart`, формат строки совместим с пакетом `crdt`.
Идентификатор устройства рождается один раз, последняя метка сохраняется
в настройках — после перезапуска часы продолжают, а не начинают заново.
Перевод системных часов назад метку не откатывает.

**Репозитории** (`LibraryRepository`, `ReadingRepository`,
`AnnotationRepository`, `LlmHistoryRepository`, `AppSettingsRepository`)
объявлены в `domain`, реализованы в `infrastructure`, собраны в одной
точке — `application/data/app_data.dart`. Тесты подсовывают туда базу
в памяти и работают с теми же репозиториями, что и приложение.

**Тема сохраняется** между запусками. Локально, без синхронизации:
ночью с телефона и днём с ПК удобны разные палитры.

**Тесты:** 106 штук, зелено. CRUD каждого репозитория, состав таблиц
и колонок, snake_case имён, включённые внешние ключи, каскад при чистке,
надгробия, изоляция аннотаций между книгами, кэш LLM (совпадение задачи,
выделения и контекста), поведение HLC при стоящих, убежавших и
переведённых назад часах.

### Решения и находки S2

**Даты хранятся строкой ISO-8601 в UTC** (`store_date_time_values_as_text`).
База читаема глазами, часовые пояса и перевод часов не сдвигают
записанное, сортировка по строке совпадает с сортировкой по времени.
Поменять это после релиза нельзя — потому и зафиксировано в `build.yaml`
сразу.

**Перечисления пишутся именами, а не номерами.** Номер молча меняется
при вставке значения в середину `enum`, и настройки читателя тихо
становятся другими. Неизвестное имя не роняет приложение, а откатывается
к значению по умолчанию: файл базы может приехать с устройства, где
стоит версия новее.

**Сгенерированный код drift в репозитории не лежит.** У сессии нет
Flutter SDK, пересобрать `*.g.dart` на месте она не может, а устаревший
сгенерированный файл в коммите — источник необъяснимых падений. Файлы
собирает CI шагом `build_runner` перед анализом, тестами и каждой
сборкой; `*.g.dart` добавлены в `.gitignore`.

**CI показывает патч форматирования, а не список файлов.** Прежний шаг
`dart format --set-exit-if-changed` называл файлы, но не говорил, что
именно в них не так, — а прогнать форматер до пуша сессия не может.
Теперь CI сам запускает `dart format`, печатает `git diff` по
Dart-файлам и валит прогон. Анализ и тесты идут дальше по уже
отформатированному коду: одна ошибка формата больше не съедает прогон
целиком. Диффом по `*.dart` шаг ограничен потому, что `flutter pub get`
переписывает `windows/flutter/generated_plugins.cmake` при добавлении
любого плагина.

**Внешние ключи и синхронизация.** Каскад включён, но при слиянии в S10
чейнджсет придётся применять в транзакции родителями вперёд — иначе
цитата, приехавшая раньше своей книги, упрётся в внешний ключ.

**Индексов по `book_id` пока нет.** На десятках книг они не окупаются;
добавятся отдельной миграцией в S5, когда появится реальная библиотека.

**Проверка на телефоне сначала показала, что тема не сохраняется.**
Ложная тревога: APK ставился поверх альфы S1, установка не прошла,
и проверялось старое приложение — то самое, которое честно писало на
экране настроек, что тема пока не сохраняется. Причина в подписи: до
релизного ключа (S13) каждая сборка подписана одноразовым отладочным
ключом раннера, а Android не обновляет приложение чужим ключом. **Перед
установкой новой альфы старую надо удалять**; предупреждение добавлено
в README.

Из этого выросли две вещи, полезные на все следующие сессии.
Во-первых, `test/data/restart_persistence_test.dart` — тесты на **файловой**
базе: все остальные работают с базой в памяти и поломку записи на диск
поймать не могут в принципе. Во-вторых, экран настроек показывает строку
сборки (`версия · коммит`, подставляется в CI через `--dart-define`):
теперь отчёт «не работает» всегда привязан к конкретному коммиту,
а не к памяти о том, какой файл качали.

### S3 — Ядро читалки на pdfrx (08.08.2026)

**Книга открывается, листается и помнит место.** Экран чтения построен на
`pdfrx` 2.4 (движок PDFium). По умолчанию на экране нет ничего, кроме
страницы; нажатие в середину показывает панели, и они уходят, как только
читатель переходит к делу. Листание — лентой сверху вниз или страница за
страницей вбок, переключается кнопкой.

**Позиция чтения** восстанавливается при открытии и записывается по
таймеру, который намеренно **не** перезапускается на каждой странице.
Перезапуск откладывал бы запись бесконечно при быстром листании, и
закрытое по питанию приложение теряло бы место. Запись случается не реже
раза в две секунды и немедленно — при уходе с экрана и при сворачивании
приложения.

**Оглавление** читается из файла один раз, разворачивается в плоский
список с отступами, подсвечивает раздел, в котором читатель находится, и
раскрывает путь к нему. Пункт, чьё назначение указывает за край книги,
показывается, но не нажимается: PDF собирают чем попало.

**Поиск по книге** идёт постранично и отдаёт найденное по ходу дела —
на тысяче страниц ждать конца, глядя на крутилку, невыносимо. Текст
страницы перед поиском нормализуется (переносы строк, двойные пробелы,
неразрывные пробелы и мягкие переносы), иначе фраза из двух слов не
найдётся, если между ними оказался перенос. Каждое совпадение показывается
фрагментом с контекстом; координаты найденного хранятся в **исходном**
тексте — они понадобятся подсветке в S6.

**Слои.** Книга приходит в приложение интерфейсом `ReaderDocument`
(`domain/reading`), а PDFium знает только `infrastructure/pdf`. Поэтому
сценарии чтения проверяются подставным документом, без движка и без
файлов, а корпус-тесты гоняют настоящий PDFium через ту же дверь, что и
приложение.

**Корпус проблемных PDF** — `test/fixtures`, 196 КБ, собирается
`tool/make_fixtures.py` (pikepdf), состав и ожидания описаны в
`test/fixtures/README.md`:

| Файл | Чем интересен |
|---|---|
| `basic_text.pdf` | 8 страниц, плоское оглавление |
| `outline_nested.pdf` | оглавление в три уровня |
| `two_columns.pdf` | двухколоночная вёрстка (пригодится S4) |
| `scan_no_text.pdf` | скан: текстового слоя нет вовсе |
| `cjk.pdf`, `rtl.pdf` | Type0/Identity-H, шрифт **не встроен**, есть ToUnicode |
| `rotated_pages.pdf` | `/Rotate` 0, 90, 180, 270 |
| `mixed_page_sizes.pdf` | четыре разных размера страниц в одном файле |
| `huge_1200_pages.pdf` | 1200 страниц |
| `encrypted.pdf` | пользовательский пароль |

Каждый файл проходит круг «открыть → извлечь текст → отрендерить
страницу», а битые — круг «понятная причина вместо падения».

**Чем открыть книгу до S5.** Полки ещё нет, поэтому добавлены выбор файла
системным диалогом (`file_selector`, без сервисов Google — условие
F-Droid) и минимальный список открывавшихся книг с прогрессом. Всё это S5
заменит настоящей библиотекой с обложками.

**Тесты:** 241 штука, зелено. Корпус PDF на настоящем PDFium, навигация и
позиция (обратимость прогресса, края книги, мусорные значения), разворот
оглавления и подсветка раздела, нормализация текста и поиск, троттлинг
записи позиции на живой базе, импорт и отпечаток файла, widget-тесты
экрана чтения (панели, ползунок, оглавление, поиск) на подставном
документе.

### Решения и находки S3

**Открыть файл дважды — осознанная цена.** Просмотрщик `pdfrx` открывает
книгу сам, и приложение открывает её ещё раз — для текста, оглавления и
поиска. Иначе тип PDFium протёк бы из инфраструктуры в интерфейс, и вся
логика чтения перестала бы тестироваться без движка. Второй разбор стоит
дерева страниц, текст читается лениво. Если на тысячестраничных книгах это
окажется заметно, в S6 можно будет разделить один документ на двоих — там
для этого уже будет повод.

**Подсветка найденного в S3 не делается.** Список результатов со
фрагментами есть, переход на страницу есть, а подсветка самого совпадения
на странице требует координат символов — это работа S6, где выделение
текста делается целиком. Обещать половину подсветки хуже, чем честно
отложить.

**Прилипание при постраничном листании тоже отложено.** Раскладка
«страница за страницей» есть, но границы страниц не притягивают прокрутку.
Это часть режимов отображения из S4, где будет вся нужная геометрия.

**PDFium в тестах приходит из `PDFIUM_PATH`.** В сборках библиотеку
приносит `pdfrx` нативным ассетом, но в среде `flutter test` этот путь
ненадёжен. CI кладёт `libpdfium.so` руками и передаёт путь переменной
окружения — единственный документированный способ указать модуль явно.
Версия взята та же, что тянет `pdfium_dart` в сборки. Инструкция для
участников — в `CONTRIBUTING.md`.

**Живые запросы drift и widget-тесты не дружат.** При отписке от потока
drift планирует уборку обычным таймером, а в widget-тестах время
подменено — оставшийся таймер валит тест сообщением «A Timer is still
pending». Лечится тем, что тест снимает дерево виджетов явно и
прокручивает ещё кадр. Там, где база не нужна по существу, тесты чтения
работают с хранилищем в памяти.

**Форматер сменил стиль.** Свежий стабильный Flutter переписал даже те
файлы, которых сессия не касалась (`build_info.dart`,
`theme_contrast_test.dart`): короткие многострочные вызовы теперь
собираются в одну строку, а длинное тело функции в именованном аргументе
переносится на следующую строку. Само по себе это безвредно, но означает,
что после каждого обновления Flutter первый прогон CI будет красным по
форматированию, пока патч не применён.

**pdfrx требует Flutter 3.41 и Dart 3.10** — PDFium приезжает нативным
ассетом через хуки сборки, а они появились именно там. Нижняя граница
поднята в `pubspec.yaml`.

**Прогресс считается по нижней границе страницы.** Открытая первая
страница из десяти — это 10 %, а последняя — ровно 100 %. При счёте по
верхней границе индикатор дочитанной книги замирал бы на 90 %, что
выглядит как ошибка.

**Двоичная арифметика в ползунке.** `11 / 340 * 340` в `double` равно
`11.000000000000002`, и честный `ceil` возвращал двенадцатую страницу
вместо одиннадцатой — ползунок прыгал бы на страницу вперёд при каждом
касании. Лечится поправкой на эпсилон, закреплено тестом обратимости на
книгах в 1, 7, 340 и 1200 страниц.

**RTL-текст извлекается не в логическом порядке.** Это свойство PDF, а не
ошибка: в файле лежит визуальный порядок. Тест проверяет, что символы
дошли и не превратились в мусор, а не их последовательность.

### S4 — Читательская рамка (08.08.2026)

Сердце миссии проекта, а не полировка: поля печатной книги нужны пальцам,
а не глазам, и на телефоне съедают до трети экрана.

**Обрезка полей идёт двумя путями.** Быстрый — по координатам символов
текстового слоя: PDFium отдаёт прямоугольник на каждый символ, и в
интерфейсе `ReaderDocument` появился `pageTextBoxes`, возвращающий их в
долях **отображаемой** страницы (поворот `/Rotate` уже применён). Пробелы
отбрасываются: концевые пробелы строк растянули бы рамку до самого края
поля, ради которого всё и затевалось. Медленный путь — по пикселям
рендера шириной 220 точек, единственный возможный для сканов: уровень
фона берётся с краёв страницы, «чернилами» считается всё, что отличается
от него больше чем на 12 % (по модулю — светлый текст на тёмном фоне
обрезается так же), а строка или столбец засчитываются, только если
чернил в них не меньше 2 %. Без этого порога пылинка на стекле сканера
сводила бы обрезку к нулю.

**Колонтитулы отбрасываются по разрыву, а не по месту на странице.**
Номер страницы отделён от тела текста пустотой вдвое с лишним большей,
чем межстрочный интервал; заголовок главы — нет. Выбрасывается не больше
одной строки сверху и снизу, и только если строк на странице хотя бы
четыре: на титуле или посвящении любая строка выглядит оторванной, а
ошибка стоила бы половины содержимого.

**Рамка округляется наружу к сетке в 0,5 %.** Соседние страницы книги
отличаются полями на доли процента, и без округления кегль слегка гулял
бы от страницы к странице — это заметно глазу сильнее, чем сами поля.
Плюс два предохранителя: рамка не бывает уже пятой части страницы (иначе
одно слово посреди листа растянулось бы на весь экран) и никогда не
бывает пустой или вывернутой — в этом случае показывается страница
целиком.

**Режимы отображения.** Страница / половина / треть / разворот. На одной
колонке половина и треть — это горизонтальные полосы; на двухколоночной
вёрстке половина — это **колонка**, а треть — половина колонки: колонка
уже и есть половина страницы, а делить её на три — не чтение, а
разглядывание. Соседние полосы налезают друг на друга на 4 % высоты,
иначе строка ровно на границе оказалась бы разрезана по горизонтали и не
прочиталась бы ни в одной из половин.

**Колонки ищутся по вертикальному просвету** — полосе, в которую не попал
ни один символ **ни одной** строки. В сплошном тексте такой полосы
посреди страницы не бывает: какая-нибудь строка обязательно её
перечеркнёт, поэтому признак почти не даёт ложных срабатываний. Просвет
ищется только в средней трети страницы и только один: трёхколоночных книг
практически не бывает, а цена ошибки — разорванный посередине текст.
Границы самих колонок берутся по крайним символам, а не по краям
просвета, иначе в колонку попала бы половина межколоночного поля и
выигрыш в кегле пропал бы.

**Смена режима не теряет места на странице.** Позиция считается по
середине текущего фрагмента: верхняя половина при переходе на трети
становится первой третью, нижняя — последней. Номер фрагмента лежит в
`reading_progress` с S2 и уезжает в базу вместе со страницей.

**Обрезанное показывается в разрешении экрана, а не растягивается.**
Фрагмент выводится через `goToRectInsidePage` просмотрщика pdfrx — это
обычный зум, поэтому PDFium перерисовывает страницу в текущем масштабе, и
мелкий шрифт не мылится. Потолок увеличения поднят с восьмикратного (по
умолчанию у pdfrx) до двадцатичетырёхкратного: на трети страницы восьми
уже не хватает.

**Светофильтры — фрагментный шейдер поверх страницы и только страницы.**
Панели, оглавление и поиск остаются в обычных цветах: ночью читатель
должен видеть, где кнопка выхода. Порядок преобразований — гамма,
контраст, сам фильтр, яркость: сначала вытягивается бледный скан, потом
разводятся текст и фон, и только потом гасится экран. Фильтры: ночной
красный монохром, тёплый (снижение синего), сепия, инверсия с двойной
инверсией картинок, плюс яркость ниже системного минимума, контраст и
гамма отдельными ползунками. Файл не меняется вовсе.

**Ручная правка рамки** — отдельный экран с превью страницы и четырьмя
краями, которые тянут пальцем. Рамка применяется ко всей книге сразу:
править её на каждой странице никто не станет. Ручная рамка главнее
автообрезки — если автомат ошибся именно на этой книге, спорить с
человеком незачем.

**Настройки живут на книгу и на ориентацию экрана** — составной ключ,
заложенный в схему ещё в S2. То, что удобно в портрете, в альбоме обычно
неудобно, и наоборот. Экран чтения к тому же уходит в полноэкранный
режим: системные панели прячутся и возвращаются жестом от края.

**Тесты: 374 штуки, зелено.** Геометрия рамки на числах (обрезка по
тексту и по пикселям, колонтитулы, минимальный размер, сетка, вывернутые
и бесконечные значения), колонки (две колонки, сплошной текст, титул в
две строки, отступ у края), деление на фрагменты во всех режимах и
обратимость смены режима, разбор рамок **всего корпуса PDF** настоящим
PDFium с проверкой, что ни на одной странице ни в одном режиме не выходит
пустого или вывернутого прямоугольника, кэш рамок (страница разбирается
один раз), сценарии контроллера (листание по фрагментам, края книги,
ориентации, запись фрагмента в базу), эталонная таблица светофильтров,
укладка цветовой матрицы через настоящий движок, договор с шейдером и
widget-тесты панели настроек и экрана правки рамки.

### Решения и находки S4

**Рамка работает в постраничном листании, а лента осталась лентой.**
Режимы отображения требуют, чтобы экран показывал ровно один фрагмент, —
это несовместимо со свободной прокруткой. Поэтому постраничное листание
стало режимом по умолчанию и получило переходы по фрагментам (нажатие в
левую или правую треть экрана), а непрерывная лента оставлена как есть:
это другой способ читать, и навязывать ему рамку значит сломать оба.

**Двойная инверсия картинок сделана по насыщенности.** Правильный способ —
инвертировать страницу целиком, а области изображений инвертировать
второй раз, — требует координат картинок на странице, а pdfrx объекты
страницы не отдаёт. Поэтому картинка отличается от текста по насыщенности
пикселя: буквы и бумага почти всегда серые, иллюстрации цветные, и
цветной пиксель инвертируется дважды, то есть остаётся собой. Цена
решения честная и записана в известные проблемы: **чёрно-белая фотография
всё-таки станет негативом**.

**Golden-тесты фильтров — таблица чисел, а не картинка.** Шейдеры в
`flutter test` не собираются вовсе, а растеризация отличается от
платформы к платформе, поэтому эталоном служит
`test/goldens/reading_filters.json` — 11 наборов настроек по 8 цветов,
посчитанных **другой** реализацией той же математики
(`tool/make_filter_goldens.py`). Совпадение двух независимых реализаций
до шестого знака практически исключает ошибку в формуле, а случайное
изменение фильтра валит тест сразу. Отдельно проверяется договор с
шейдером: состав и порядок uniform-переменных в `.frag` обязаны совпадать
с тем, что в них пишет код.

**`ImageFilter.shader` работает только на Impeller.** На движках без него
(сегодня это Windows и `flutter test`) слой фильтра сам переходит на
цветовую матрицу `ColorFilter.matrix`. Матрицей не выражаются две вещи:
гамма нелинейна, а двойная инверсия смотрит на каждый пиксель. Гамма
заменяется линейным приближением по методу наименьших квадратов — при
гамме 1 приближение точное, так что нетронутая гамма не портит картинку;
инверсия становится простой. Проверка `ImageFilter.isShaderFilterSupported`
делает выбор пути сама.

**Вывернутая рамка «чинилась» растяжением.** Прямоугольник с правым краем
левее левого сначала растягивался до минимального размера и только потом
проверялся — и проходил проверку, превратившись в осмысленный на вид
квадрат посреди страницы. Теперь перевёрнутый прямоугольник отбрасывается
до всякой нормализации. Поймано тестом, который писался ровно на этот
случай.

**`1 - 0.9` в double чуть меньше `0.1`.** Ограничитель ручной рамки не даёт
сделать её уже десятой доли страницы, а тест на это падал: ширина
получалась `0.09999999999999998`. Второй случай за проект, когда двоичная
арифметика ловится в геометрии (первый был в ползунке прогресса в S3).

**Свежий `dart format` собирает короткие многострочные вызовы в одну
строку.** Патч из лога прогона снова оказался длиннее самих правок кода.
Практическое следствие для будущих сессий: не разбивать вручную то, что
влезает в 80 колонок, и не ставить хвостовую запятую в коротких литералах —
она заставляет форматер разложить список по строкам.

### S4.1 — Правки по проверке на устройствах (09.08.2026)

Первая проверка живыми руками сразу нашла то, чего не видно из кода.

**Половина страницы не увеличивала текст вовсе — и это была не ошибка
реализации, а геометрия.** Полоса вдвое ниже страницы, но **той же
ширины**, а в вертикальный экран телефона страница вписывается именно по
ширине: масштаб упирается в ширину и не меняется, сколько ни дели
страницу по горизонтали. Читатель видел ровно ту же страницу, только с
пустотой снизу.

Кегль растёт лишь тогда, когда широкую и низкую полосу показывают на
широком и низком экране. Поэтому **выбор режима сам поворачивает
чтение**, а приложение поворачивает экран принудительно
(`SystemChrome.setPreferredOrientations`) — автоповорот у многих выключен
насовсем, и полагаться на него нельзя. Кнопка поворота стоит в верхней
панели: читатель вправе не согласиться.

Числа закреплены тестом `fragmentScale` на содержимом А4 и экране
1080×2400: половина в портрете равна целой странице (1.00), половина в
альбоме — 1.34, треть в альбоме — 2.01. Двукратное увеличение, ради
которого затевались режимы, даёт именно **треть страницы в альбомной
ориентации**, а не половина; половина ближе к полутора.

**Зоны листания следуют направлению деления.** Полосы идут сверху вниз —
нажимать надо сверху и снизу; колонки, целые страницы и развороты
листаются привычно, слева и справа. Направление берётся по первому
переходу и не меняется в пределах страницы: зоны, уезжающие под рукой на
последнем фрагменте, — худшее, что можно сделать с листанием.

**Разворот больше не разрезан чёрной полосой.** Страницы пары стоят
вплотную (`_layoutSpreads`), зазор остался только между разворотами.
Добавлен режим **«полразворота»**: верх обеих страниц, потом низ. Колонки
внутри страниц его не делят — строка идёт через обе страницы сразу.

**Перестановки в интерфейсе.** Оглавление переехало вниз, правее шкалы
прогресса: и то, и другое отвечает на вопрос «где я в книге», а наверху
эта кнопка путалась с настройками. Способ листания (лента или по
страницам) ушёл в панель настроек, а освободившееся место занял поворот
чтения. Способ листания и положение экрана хранятся как настройки
устройства (`ui.page_flow`, `ui.reading_rotation`), а не книги.

**Ночной красный вполсилы по умолчанию.** Полный монохром режет глаз
сильнее, чем помогает.

**Режим отображения переносится между ориентациями.** Экран повернулся
ради самого режима — обнаружить после поворота целую страницу вместо
выбранной половины было бы издевательством. Рамка, фильтр и яркость
по-прежнему свои у каждой ориентации.

**Тесты: 391, зелено.**

### S4.2 — Жёсткая раскладка вместо зума (09.08.2026)

Вторая проверка руками отвергла саму механику показа. Читалка наводила
объектив на кусок страницы — зумом и прокруткой просмотрщика, — и это
чувствовалось как фокус: масштаб плавал, страницу можно было увести
пальцем, посадка была неточной.

**Теперь чтение по страницам не масштабируется вовсе.** Лист — одна
страница или две страницы разворота рядом — вписывается в экран целиком,
и масштаб определяется только размерами листа и экрана. Он одинаков на
каждой странице книги и не зависит ни от жестов, ни от истории.

| Режим | Что видно |
|---|---|
| Страница | страница целиком в вертикальном экране, все поля на месте |
| Половина | горизонтальный экран, боковые и верхнее поля целы, срезан ровно низ; следующий фрагмент — низ страницы |
| Разворот | две страницы рядом, вписанные в горизонтальный экран |

**Обрезка полей выключена по умолчанию** и осталась отдельной
возможностью в настройках. Страница показывается такой, какой её
свёрстали: предсказуемость оказалась дороже пары сантиметров экрана.

**Зум и свободная прокрутка никуда не делись** — они живут в непрерывной
ленте. Это другой способ читать, и там они на своём месте.

**Как это сделано.** Вместо `PdfViewer` с его `goToRectInsidePage` в
постраничном чтении работает собственный виджет `ReaderSheet`: страницы
рисует `PdfPageView` из pdfrx в точно заданном размере, а нужный
прямоугольник выводится сдвигом внутри `ClipRect`. Рендер по-прежнему
идёт в разрешении экрана — `PdfPageView` рисует страницу под размер
своего виджета.

Математика вынесена в `domain/reading/sheet_placement.dart` и проверяется
**обратным пересчётом**: по готовой раскладке восстанавливается
прямоугольник, реально попавший на экран, и тест утверждает не формулу,
а то, что увидит читатель, — «левое поле на месте, низ обрезан».

**Тесты: 403, зелено.**

### S4.3 — Чёрный экран вместо книги (09.08.2026)

Проверка на устройстве: «страницы вначале отображались не все, а потом
вообще чёрный экран». Причина оказалась ровно в шве между слоями.

**Книга открывалась дважды.** Контроллер открывает её для текста, поиска
и оглавления — целиком, с `useProgressiveLoading: false`, потому что
число страниц нужно сразу. А показ страницы, введённый в S4.2, открывал
**вторую копию** через `PdfDocumentViewBuilder.file`, и та грузилась
прогрессивно: список страниц наполнялся постепенно. Пока нужная страница
в него не попала, лист получался пустым — а пустой лист рисовался просто
фоном темы, то есть чёрным прямоугольником. Чем дальше в книгу, тем выше
шанс опередить загрузку, отсюда и «сначала не все, потом вообще ничего».
Вдобавок большая книга занимала вдвое больше памяти.

**Теперь страницу рисует тот самый документ, который уже открыт.** У
`ReaderDocument` появился `engineDocument` — единственная намеренная щель
в интерфейсе, с объяснением прямо в документации: рисовать обязан тот же
файл, который читает текст. Закреплено корпус-тестом на
тысячестраничной книге: движок отдаёт документ, и страниц в нём столько
же, сколько знает приложение.

**Пустой лист больше не молчит.** Вместо чёрного прямоугольника
показывается ожидание: по молчаливой заливке невозможно отличить
«страница ещё грузится» от «книга сломана», и на это ушла целая итерация
проверки владельцем.

Общий урок на будущее: **любое «ничего не видно» должно выглядеть как
состояние, а не как фон.** Заливка цветом темы в роли пустого состояния —
готовая ловушка.

**Тесты: 404, зелено.**

### S4.4 — Листание, зум и указатель места (09.08.2026)

**Зоны листания всегда слева и справа.** Привязка к направлению деления
(полосы — сверху вниз, колонки — вбок) выглядела стройно и на практике
заставляла каждый раз вспоминать, куда нажимать именно в этом режиме.
Привычка «вправо значит дальше» сильнее любой логики раскладки. Прежняя
функция `fragmentFlowFor` удалена вместе с тестами: неиспользуемая
абстракция гниёт быстрее кода.

**Половины делятся чёткой линией.** Нахлёст в 4 % задумывался как забота
о строке на границе, но на деле повторял её на обоих экранах — глаз
видит знакомый текст и теряет место. Разрезанная строка оказалась ценой
меньшей, чем сбитое чтение.

**Приблизить можно, но ненадолго.** Щипок увеличивает лист до
пятикратного, и как только пальцы убраны, страница возвращается на
место. Так разглядывание схемы не превращается в потерянный масштаб,
который непонятно как вернуть. Возврат отключается в настройках —
переключатель «Возвращать масштаб».

**Настройки чтения больше не делятся по положению экрана.** Прежнее
решение (своя рамка и свой фильтр для портрета и альбома) звучало
разумно, а на устройстве сбивало красный фильтр при каждом повороте.
Фильтр, рамка и режим — свойства **книги**: читатель настроил её один
раз и ждёт такой же после поворота, а когда появится синхронизация —
и на другом устройстве. Колонка `orientation` в схеме осталась и
заполняется всегда одинаково (`kSettingsSlot`): переписывать таблицу
с данными живых читателей ради снятого признака дороже, чем не
пользоваться колонкой.

**Указатель места в полях вокруг страницы.** Страница почти никогда не
совпадает с экраном по пропорциям, и поля пустуют: в вертикальном чтении
сверху и снизу, в горизонтальном — слева и справа. Там теперь стоит
книга: стопка прочитанного растёт, стопка оставшегося тает, рядом —
«страница из скольких». Указатель **не исчезает вместе с панелями**:
именно без панелей читатель и теряет представление о том, где он.
Выбор поля — чистая математика в `domain/reading/progress_slot.dart`;
если поля нет вовсе, указатель честно сообщает, что лёг поверх страницы,
и получает подложку.

**Тесты: 404, зелено.**

### Решение владельца о настройках и облаке (09.08.2026)

Настроек отображения будет **два уровня**, и оба остаются на устройстве:

- **Мастер-настройки** — как открывать любую книгу по умолчанию (режим, положение экрана, фильтр, яркость). Живут в меню приложения.
- **Настройки книги** — поправка для конкретного файла: этой книге не годится половина страницы, зато годится разворот. Правятся прямо в чтении, как сейчас.

**В облако уходит только прогресс чтения** и то, что читатель создал сам: цитаты, заметки, закладки. Настройки отображения не синхронизируются — удобное на телефоне почти никогда не удобно на большом экране. Но перенести их **по явной кнопке** с другого устройства можно будет: разово и целиком.

Работа по мастер-настройкам добавлена в S12; сейчас работает только уровень книги. Записано в `CLAUDE.md`, `docs/strategy_pdf_reader.md` §9 и `docs/dev_plan_sessions.md`.

### S4.5 — Строки не режутся, книга вместо полоски (09.08.2026)

**Граница половин и третей проходит между строк.** Геометрическая
середина почти всегда попадает на строку и рассекает её: верхняя
половина остаётся на одном экране, нижняя на другом, и читать нельзя ни
там, ни там. Теперь `PageFrame` несёт ещё и просветы между строками
(`lineBreaks` по тем же координатам символов, что и обрезка полей), а
граница переезжает в ближайший просвет — но не дальше 18 % высоты полосы,
иначе полосы разъедутся и кегль начнёт скакать от экрана к экрану.
У скана строк нет, и там деление остаётся геометрическим.

Так закрывается и вторая половина жалобы: повторов не нужно вовсе, потому
что резать по живому больше не приходится. Перечитывать последнюю строку
после перелистывания не надо.

**Указатель места стал книгой.** Была полоска с насечками — теперь
раскрытая книга сбоку: две стопки страниц, сходящиеся у корешка, левая
растёт, правая тает. Толщина зависит от объёма файла, так что брошюра и
том выглядят по-разному. Под рисунком — «страница из скольких».

**Тесты:** деление между строк проверяется прямо: берётся ровный блок
строк, страница делится пополам, и тест утверждает, что **ни одна строка
не пересекает границу**. Плюс проверки на то, что граница не уезжает
далеко, что без просветов деление остаётся геометрическим и что полосы
по-прежнему стыкуются без щели и без повтора.

### S4.6 — Строки не теряются, книга-указатель, планы (10.08.2026)

Третья проверка руками. Замечания владельца: текст иногда обрезается в
режимах половины и трети; вместо книги-указателя видны одни цифры
«страница X/Y». Разбор показал, что оба замечания относятся к сборке
**v0.4.4**: правки S4.5 лежали в `main` невыпущенными. Но у каждого
из них нашлась и вторая, настоящая половина.

**У скана теперь тоже есть строки.** S4.5 научила границу полос
попадать в просвет между строками — но только там, где есть текстовый
слой. У скана `breaks` были пусты, и половина резалась ровно по
геометрической середине, то есть почти всегда по живой строке. Теперь
просветы берутся из **того же пиксельного профиля**, который и так
считается ради обрезки полей: пустые горизонтальные полосы внутри
содержимого — это и есть междустрочья. Профиль уже посчитан, так что
просветы достались бесплатно. Ширина разбора поднята с 220 до 320
точек: на 220 строки скана местами слипались в одну полосу, и делить
было негде.

**Где просвета нет — строка повторяется, а не пропадает.** Испорченный
текстовый слой, страница-картинка, набор без междустрочья: бывает, что
резать между строк негде вовсе. Прежде граница просто рассекала строку,
и та терялась — верхняя половина на одном экране, нижняя на другом.
Теперь такая граница расходится на `kBlindOverlap` (3 % высоты полосы,
примерно строка), и строка **повторяется** на обоих экранах.
Несимметричный размен сделан осознанно: потерянную строку читатель не
восстановит никак — он даже не узнает, что её не видел; повторённую
пропустит глазом. Там, где просвет нашёлся, нахлёста по-прежнему нет.

**Полосу можно уменьшить щипком, и это запоминается.** Полоса вписана в
экран вплотную, и её крайняя строка приходится ровно на границу экрана —
где у современного телефона закруглённый угол, вырез камеры и жестовая
зона. Щипок внутрь теперь уменьшает полосу до 70 % и **остаётся так для
этой книги**: подгонка делается один раз под кегль книги и под это
устройство, повторять её на каждой странице читатель не должен. Щипок
наружу остался тем, чем был, — временным увеличением с возвратом. То же
значение правится ползунком «Запас по краям» в панели настроек: жест
надо ещё найти, а панель отвечает на вопрос «как это вообще делается».

Лист при этом обрезается **ровно по фрагменту**: иначе в освободившийся
запас заглядывала бы соседняя полоса, а торчащая половина строки сбивает
чтение сильнее, чем пустое поле.

Значение живёт в настройках книги — новая колонка `strip_fit` и первая в
проекте миграция схемы (версия 1 → 2). Миграция проверяется на настоящем
файле базы: база откатывается к версии 1 теми же средствами, какими её
создавал drift, и открывается заново — как откроется база читателя,
обновившего приложение. Настройки при этом обязаны сохраниться, а новая
колонка — прийти со значением по умолчанию.

**Указатель места переписан.** Прежний рисунок был двумя клиньями,
сходящимися к корешку, и в узком поле исчезал совсем: ширина
считалась как «поле минус 8», и при тесном поле от рисунка оставалось
меньше 12 точек — читатель видел одни цифры. Теперь это два блока
страниц по сторонам корешка, левый растёт, правый тает; ширина никогда
не падает ниже 28 точек; обложка — тонкая черта во всю ширину, чтобы в
самом начале книги пустая левая половина не выглядела поломкой.
Прочитанное рисуется акцентным цветом **текста**, а не заливки: опорный
акцент `#A32F35` даёт к фону 2.86:1, и стопка на нём была еле видна.
Геометрия стопок вынесена в статические функции и проверяется обычным
тестом на числах, а не глазом на скриншоте.

**Планы и стратегия дописаны** (замечание 3 владельца): два уровня
настроек уже были записаны 09.08, к ним добавлено, что настройки книги
предлагаются **сразу после открытия**, а в S12 добавлена новая функция —
**автоматический светофильтр по времени суток, включённый по умолчанию**
(утро светлый, день сепия, вечер и ночь красный), с пояснением про
циркадные ритмы в двух фразах. Геолокация для расчёта заката
отвергнута: разрешение на местоположение ради светофильтра — плохой
обмен, а в открытом проекте ещё и подозрительный.

**Тесты: 438, зелено** (было 404). Новое: просветы скана на числах и на
корпусе, повтор строки при слепой границе, запас по краям в раскладке и
окно фрагмента, миграция схемы 1 → 2 на настоящем файле базы, геометрия
стопок указателя, ползунок запаса в панели.

**Щипок внутрь пришлось разрешить отдельно.** `InteractiveViewer` с
запасом границ по умолчанию **не даёт** уменьшить масштаб: он не
разрешает отвести края листа внутрь окна, и жест молча ничего не делал бы.
Запас границ выставлен большим, а чтобы страницу по-прежнему нельзя было
увести пальцем, чистое перетаскивание (масштаб не менялся) отменяется на
отпускании независимо от переключателя «Возвращать масштаб».

**Логи CI в этой сессии читались через браузер владельца** (расширение
Claude в Chrome): страница прогона под своим аккаунтом отдаёт и сводку,
и полный лог, и аннотации. Это снимает главное неудобство, описанное в
`CLAUDE.md`. Заодно выяснилось, что **анонимные страницы GitHub сильно
закэшированы**: без входа страница прогонов CI показывала два прогона от
4 августа при сорока девяти реальных, а страница релизов — один релиз из
девяти. Вывод «CI не запускается» из таких страниц делать нельзя; сессия
чуть не сделала.

### S4.7 — Страница гаснет, а не обрезается; дроби и замок в чтении (23.08.2026)

Четвёртая проверка руками. Три замечания владельца, и каждое — про то,
что читалка отняла у читателя контроль.

**Страница в половине и трети больше не обрезается.** Прежде от неё
оставалась ровно читаемая полоса, а всё прочее исчезало в фоне — книга
ощущалась разрезанной. Теперь лист рисуется целиком, а всё за пределами
полосы гаснет: сила затемнения — настройка книги, по умолчанию 60 %.

Тут есть геометрия, которую стоит записать, чтобы к ней не возвращаться.
Полоса вписана в экран, поэтому лист в режиме половины вдвое выше
экрана, а в трети — втрое. **Затемнённая часть страницы почти всегда
лежит за краем экрана, и показать её там негде.** Решение владельца:
она и не обязана быть видна всё время — важно, что она **есть**.
Отперев замок и сжав страницу щипком, читатель видит весь лист: светлую
полосу и тёмное вокруг неё. Ради этого с листа снят клип по краю экрана
— обрезает теперь только сам просмотрщик, уже после преобразования.
Прежний клип обрезал бы страницу и после щипка, и уменьшение показывало
бы ту же полосу, только мельче.

**Кнопки ½ и ⅓ переехали в верхнюю панель чтения**, левее поворота.
К делению возвращаются по десять раз за книгу, а лежало оно через два
нажатия в панели, которая закрывает собой ту самую страницу, по которой
принимается решение. Повторное нажатие возвращает страницу целиком:
кнопка включает режим и она же его выключает. Из панели настроек
половина и треть убраны совсем, там остались страница и развороты.
Дробь нарисована цифрами, а не символами `½` и `⅓`: в системном шрифте
их может не быть, и кнопка стала бы пустым прямоугольником.

**Поиск уехал вниз, к оглавлению.** Не по вкусу, а по ширине: с двумя
дробями и замком верхняя панель перестала помещаться в телефон в
портрете, и заголовок книги съедался до многоточия. Оглавление и поиск
отвечают на один вопрос — «где я в книге», — и внизу, у шкалы
прогресса, им место.

**Замок вместо возврата масштаба.** Прежде щипок наружу увеличивал
страницу, пока пальцы на экране, и отпускал её обратно; щипок внутрь
запоминался как запас по краям. Владелец сообщил, что на устройстве это
не работает так, как задумано, и попросил обычное поведение
просмотрщика. Теперь в панели есть замок:

| Замок | Что можно |
|---|---|
| Заперт (по умолчанию) | ничего: страница стоит там, где её положила раскладка, случайное движение руки её не собьёт |
| Отперт | двигать и масштабировать пальцами, как в любом просмотрщике; страница **остаётся** в том виде, в каком её оставили — в том числе после перелистывания |

Уменьшать разрешено до пятой части: чтобы увидеть весь лист в режиме
трети, надо сжать втрое, и предел взят с запасом. Запас границ
просмотрщика поднят с 1200 до 2000 точек — иначе он молча съедает жест
сжатия, не разрешая отвести края листа внутрь окна.

Запирание не сбрасывает масштаб — в этом и смысл: настроил и запер.
Но страницу, которую **только сдвинули**, не меняя масштаба, замок
возвращает на место: сдвинутая на палец страница выглядит поломкой, а
при запертом замке вернуть её было бы нечем.

**Схема 2 → 3.** Новая колонка `dim_outside` в настройках книги.
Миграция проверяется двумя путями: с версии 1 (как у читателя, который
пропустил обновление) и с версии 2.

**Тесты: 459, зелено** (было 438). Новое: путь тени на числах (что
накрыто, что осталось светлым, что за краем листа), кнопки-дроби
(включение, выключение повторным нажатием, переключение между дробями,
подсветка выбранного), границы читаемой полосы без подрезки экраном,
признак нетронутого масштаба, затемнение в контроллере и в панели,
миграция 1 → 3 и 2 → 3 на настоящем файле базы.

### Решения и находки S4.7

**Тень рисуется правилом «чёт-нечет».** Путь тени — это лист с дыркой
на месте читаемой полосы: два вложенных прямоугольника и
`PathFillType.evenOdd`. Проверяется не картинка, а смысл: тест берёт
точку и спрашивает, накрыта ли она. Точка в полосе — светлая, точка на
странице вне полосы — тёмная, точка за краем листа — не тронута вовсе
(гаснет страница, а не экран).

**Тень не клипуется по краю экрана** и рисуется за пределами своего
виджета намеренно: она обязана накрывать те части листа, которые
въедут в кадр после щипка.

**`fragmentViewport` заменён на `fragmentBounds`.** Прежняя функция
подрезала окно фрагмента краем экрана — это было нужно клипу, которого
больше нет. Подрезка сломала бы тень: при сжатии страницы дырка
осталась бы на месте края экрана, а не на месте полосы.

**Ключ должен стоять на самой кнопке, а не на обёртке.** Тест
`find.byKey` находил обёртку `_FractionButton`, и запрос свойств
`IconButton` падал на ровном месте. Нажатие при этом работало — поэтому
из трёх тестов кнопки упал ровно один.

**Хвост вывода тестов в аннотации бесполезен.** Логи прогона закрыты для
неавторизованных, а сессия видела только последние сорок строк — то есть
тесты, которые **прошли**: упавшие уехали вверх на сотни строк. Теперь
CI вынимает их отдельно, по метке `[E]` расширенного отчёта, и печатает
аннотацией «Упавшие тесты». Патч форматирования по той же причине
печатается целиком, а не хвостом.

**Формат снова поехал сам собой.** Свежий стабильный Flutter переписал
`pdf_corpus_test.dart`, которого сессия не касалась: длинный вызов
`test(имя, () async {…}, timeout: …)` он теперь собирает в блочную
форму. Третий раз за проект (S3, S4, S4.7) — и каждый раз первый прогон
после обновления Flutter красный по форматированию.

### S5.1 — Приём файла без копирования (23.08.2026)

Книга в 73 МБ роняла приложение раньше, чем файл доходил до нашего кода.
Чинилась не обработка ошибки, а способ приёма файла.

**Книга больше не копируется в приложение.** Место книги описывает
`BookSource` (`domain/library/book_source.dart`) — три вида: обычный путь
(Windows), закреплённая ссылка `content://` (Android) и наша копия
(запасной путь). Всё приложение работает с источником, а не со строкой
пути: `Book.filePath` заменён на `Book.source`.

**Пикер сменён на `fast_file_picker`.** Прежний `file_selector` на
Android вычитывал выбранный файл **целиком в память**, а потом писал
копию в кэш: на 73 МБ он растил буфер до 146 МБ, держал оба разом и
упирался в потолок кучи. Новый пакет сделан поверх того же
`file_selector`, но файл при выборе не читает вовсе — отдаёт имя и
ссылку. Падение исчезло у источника, на файлах любого размера.

**Чтение идёт по файловому дескриптору.** `saf_util` отдаёт дескриптор
от `openFileDescriptor`, дальше книга читается кусками через
`PdfDocument.openCustom`, а сам колбэк зовёт `pread` из libc напрямую
через FFI. Ни копии, ни перехода через платформенный канал на каждое
чтение страницы. Тем же приёмом открывают `content://` нативные
просмотрщики на PDFium.

**Разрешение на ссылку закрепляется** — иначе книга открывается только
до конца процесса, а завтра «пропадает». Это единственное, чего не умеют
готовые пакеты, и ради него написано ~25 строк Kotlin прямо в
`MainActivity`: один канал, два вызова системного API. Своего плагина не
заводилось — плагин это отдельный пакет со своим pubspec и своей жизнью,
а работы тут на два вызова.

**Копия осталась запасным путём** — для провайдеров, чья ссылка не
годится для перескоков (облачные хранилища отдают трубу, а не файл).
Перенос идёт потоком в отдельном изоляте буфером **постоянного** размера:
именно этим он и отличается от того копирования, которое роняло
приложение. Такую копию приложение считает своей и удаляет вместе с
книгой; чужой файл не трогается никогда.

**Потерянный доступ — состояние, а не падение.** Файл переименовали,
унесли карту памяти, отозвали разрешение — экран «книга не открылась»
получил кнопку «Выбрать файл заново». Идентификатор книги при этом
прежний, поэтому место чтения, цитаты и заметки остаются на месте: они
принадлежат книге, а не файлу.

**Тесты: 502, зелено** (было 459). Новое: источник туда и обратно и
строки из базы прошлых версий; чтение кусками с любой позиции; перескоки
по книге, позиция дескриптора после `pread`, чтение за концом книги;
опознание трубы; потоковый перенос на файле вчетверо длиннее буфера и на
настоящей трубе; закрепление ссылки, отозванное разрешение, отказ
провайдера закрепить; перевыбор файла на экране чтения; **весь корпус
PDF, прочитанный по дескриптору**, со сверкой с чтением по пути.

### Решения и находки S5.1

**Стратегия обещала свой мини-плагин на Kotlin — он не понадобился.**
`saf_util` 3.1.0 (тот же автор, что и у `fast_file_picker`, BSD-3) уже
умеет `getFileDescriptor`, `closeFileDescriptor` и сведения о документе.
Не умеет он одного — закрепления разрешения на **единственный** документ:
`persistablePermission` там есть только у выбора папки, а
`hasPersistedPermission` сравнивает идентификатор дерева и на ссылке
одиночного документа не годится. Поэтому из плана «~60 строк Kotlin в
своём плагине» осталось 25 строк в `MainActivity`, и те — про одно
системное действие.

**`saf_stream` не понадобился тоже.** Пакет умеет копировать SAF-файл
нативно, но тянет за собой `jni` и — главное — проверить его в CI нельзя
никак: это Android-плагин. Перенос по дескриптору пишется в тридцать
строк, работает и с файлом, и с трубой, идёт в отдельном изоляте и
**проверяется на Linux-раннере целиком**. Зависимость, которую нельзя
протестировать, дороже кода, который можно.

**Дескриптор из libc на Linux и на Android — один и тот же.** Отсюда
главный выигрыш сессии: корпус-тест открывает фикстуры через настоящий
`open` из libc и гоняет по ним весь путь «дескриптор → `pread` →
`openCustom` → PDFium», сверяя число страниц, текст, геометрию и растр с
чтением по пути. То, что в плане значилось «проверяется только на
устройстве», проверяется в CI — кроме скорости.

**Труба опознаётся по `lseek`.** Провайдер вправе отдать не файл, а
трубу; по ней нельзя вернуться назад, а PDF без этого не читается вовсе.
`lseek(fd, 0, SEEK_SET)` на трубе возвращает −1 — это и есть признак, по
которому хранилище решает копировать. Проверяется настоящей трубой из
`pipe()`, а не заглушкой.

**Колонку `file_path` переименовывать не стали.** Теперь в ней лежит
источник строкой (`file:`, `copy:`, `doc:`), а строка без известного вида
читается как обычный путь — так в базе лежат книги, заведённые до S5.1.
Миграции нет вовсе: форма колонки не изменилась, а переписывать таблицу с
книгами живых читателей ради названия колонки дороже. Закреплено тестом
на строке из базы прошлой версии, включая `C:\books\…`: буква диска
похожа на вид источника ровно до того, как посмотреть на список видов.

**Отпечаток книги считается через тот же интерфейс, что и чтение.** У
документа Android пути нет, а отпечаток нужен ему так же, как файлу:
именно он связывает книгу с её цитатами и местом чтения, когда файл
выбирают заново. Поэтому `fileFingerprint(path)` стал
`bookFingerprint(BookHandle)`, а версия по пути осталась удобной обёрткой.

**Лента больше не открывает книгу второй раз.** S4.3 починила это для
постраничного чтения, а непрерывная лента по-прежнему открывала файл по
пути своим `PdfViewer.file`. У документа Android пути нет вовсе, так что
выбора не осталось: лента получает `PdfDocumentRefDirect` с
`autoDispose: false` и рисует **тот самый** документ, который открыл
контроллер. Заодно ушёл двойной расход памяти на большой книге.

**Арифметика над указателями в FFI обойдена намеренно.** Каждый кусок
читается в начало своего буфера и копируется на своё место в буфере
движка. Одна лишняя операция копирования на несколько килобайт — цена за
то, чтобы не зависеть от того, какая форма смещения указателя доступна в
текущем SDK: `elementAt` объявлен устаревшим, а `operator +` появился не
всегда и не везде.

**Читать результаты CI из сессии стало можно.** Логи прогона закрыты для
неавторизованных, `api.github.com` закрыт прокси контейнера, а анонимные
страницы GitHub закэшированы на недели — страница прогонов в этой сессии
показывала два прогона от 4 августа при полусотне реальных. Расширение
Claude в Chrome, которым читали логи в S4.6, в этой сессии не
подключилось. Поэтому CI теперь сам кладёт итог и вывод в сиротскую ветку
**`ci-report`**: `git fetch origin ci-report && git show
origin/ci-report:report.md`. Git из сессии работает всегда и ничего не
кэширует.

## Известные проблемы после S5.1

- ~~Книга тяжелее полусотни мегабайт не открывается вовсе~~ — исправлено
  в S5.1: файл при выборе не читается, а книга открывается по
  дескриптору без копии. Осталась проверка на устройстве: сколько
  обращений на чтение делает pdfrx на книге в сотню мегабайт и не
  окажется ли чтение кусками медленнее копии. Из сессии это не
  выясняется никак.
- **Закреплённых ссылок Android держит ограниченное число на
  приложение** — сотни. Для библиотеки в тысячи книг это потолок; когда
  он окажется близок, часть книг придётся переводить на копии. Пока
  ссылка отпускается при снятии книги с полки, и этого хватает надолго.
- **Облачная книга копируется целиком.** Провайдер, отдающий трубу
  вместо файла, заставляет перенести книгу в приложение: по трубе PDF не
  читается в принципе. Место в этом случае занимается дважды — честная
  цена за то, чтобы не притворяться, будто файл локальный.
- **Чтение по дескриптору идёт на изоляте интерфейса.** Колбэк движка
  вызывается в цикле событий, и системный вызов в нём блокирующий. На
  локальном файле это микросекунды, но на книге, лежащей на медленном
  носителе, может начать чувствоваться. Если окажется заметно — колбэк
  переносится в изолят, и это правка на десяток строк.
- **На Windows фильтр беднее.** Шейдерные фильтры требуют Impeller,
  а Windows-сборка идёт на Skia: гамма там приближённая, а инверсия
  простая — картинки станут негативами. Уйдёт само, когда Impeller на
  Windows перестанет быть предварительным.
- **Чёрно-белая фотография при инверсии станет негативом.** Картинка
  отличается от текста по насыщенности, а у серой фотографии её нет.
  Правильное решение требует координат изображений на странице; вернуться
  к нему стоит, если pdfrx когда-нибудь начнёт отдавать объекты страницы.
- **Скан с чёрной рамкой по краю не обрезается.** Сплошная тёмная полоса
  вдоль края — такое же «содержимое» с точки зрения пиксельного разбора,
  как и текст. Лечится ручной рамкой; отдельного распознавания рамок
  сканера делать не стали.
- **В непрерывной ленте режимы отображения не действуют** — там нет
  понятия «один фрагмент на экран». Обрезка и фильтр работают и в ней.
- **Указателя места в ленте тоже нет.** Он живёт в листе постраничного
  чтения; в ленте место показывает полоса прокрутки просмотрщика.
- **Запас по краям полосы не действует в ленте** — там масштаб выбирает
  сам читатель, и подгонять нечего.
- **Затемнённую часть страницы видно только при сжатии.** Полоса
  занимает экран целиком, и соседние полосы физически лежат за его
  краем: показать их, не уменьшив страницу, негде. Решение владельца от
  22.08.2026 — так и надо: важно, что они есть и до них можно добраться
  щипком.
- **Увеличение щипком растягивает уже отрисованную страницу.** Мелкий
  шрифт при этом мылится: страница перерисовывается в новом разрешении
  только когда меняется раскладка — то есть при смене режима или запаса
  по краям. Резкое увеличение потребовало бы пересчёта раскладки на
  каждый жест, а страница целиком растеризуется в память: на двойном
  увеличении это уже десятки мегабайт.
- **Отпертую страницу можно увести далеко за край.** Запас границ
  просмотрщика — 2000 точек, и настойчивым перетаскиванием страницу
  можно отправить почти в пустоту. Лечится замком: он возвращает
  сдвинутую страницу на место, если масштаб не менялся.
- ~~В постраничном чтении нет зума совсем~~ — в S4.7 масштаб и
  перемещение стали обычными и запираются кнопкой замка.
- ~~Книга открывается дважды~~ — исправлено в S4.3: страницу рисует тот
  же документ, который открыл контроллер.
- **Двукратное увеличение даёт треть страницы, а не половина.** Половина
  в альбомной ориентации крупнее целой страницы примерно в полтора раза:
  так сходятся пропорции полосы и экрана телефона. Обещание «половина
  удваивает кегль» из README и CLAUDE.md строго верно только для экранов,
  чьи пропорции совпадают с половиной страницы.
- **На Windows поворот чтения ничего не делает.** `setPreferredOrientations`
  — мобильный вызов; на десктопе положение окна выбирает человек.
- **Прилипание к границам страниц по-прежнему не сделано.** В постраничном
  листании переходы идут по фрагментам, и прилипание там не нужно;
  в ленте оно так и осталось отложенным.

## Известные риски и решения по ним

| Риск | Решение |
|---|---|
| Установка APK «из неизвестных источников» отпугнёт часть аудитории | Инструкция на странице проекта, Obtainium для автообновлений, IzzyOnDroid и RuStore как привычные каталоги |
| Обязательная верификация Android-разработчиков (пилот с 30.09.2026, глобально в 2027) затронет и сайдлоад | Отслеживать; при необходимости пройти верификацию в Android Developer Console |
| Автообрезка полей ошибётся на нетипичном макете | Ручная правка рамки + корпус проблемных PDF в тестах |
| Красная тема окажется нечитаемой | Автотест контраста WCAG AA + четыре альтернативные темы из коробки |
| Мелкий шрифт останется мылом при увеличении | Рендер обрезанной области в разрешении экрана, а не растяжение растра — заложено в постановку S4 |
| Злоупотребление прокси при открытом коде | Токен сборки из GitHub Secrets, лимит на устройство, дневной потолок, режим «свой ключ» |
| Бесплатный тир Gemini обучается на данных пользователей | Не использовать. Groq + локальная модель по умолчанию для чувствительного текста |
| Единственный транспорт синхронизации однажды окажется недоступен | `SyncBackend` держится сменным: Drive, WebDAV, файл вручную. Движок слияния от транспорта не зависит вовсе |
| Потеря релизного ключа Android делает обновление невозможным | Резервная копия keystore сразу при создании в S13 |

## Проверка владельцем после S5.1 (15 минут, телефон)

Ставить **v0.5.1-alpha** — или «Свежую сборку из main». Старую версию
перед установкой удалить: сборки подписаны одноразовым отладочным ключом
раннера, и Android не обновляет приложение чужим ключом.

1. **Тот самый учебник на 73 МБ.** Открыть его и ещё пару крупных книг.
   Прежде приложение падало при выборе файла — теперь оно обязано
   открыть книгу любого размера.
2. **Скорость листания — самое важное.** Полистать крупную книгу
   подряд и перескоками (ползунок, оглавление). Книга читается кусками
   прямо из файла, и если листание заметно медленнее прежнего, это ответ
   про шаг 2: откат на копию стоит одну строку. Сравнить есть с чем —
   книги поменьше открывались и раньше.
3. **Книга открывается после перезапуска без повторного выбора.**
   Закрыть приложение (смахнуть из списка задач), открыть заново,
   нажать книгу на полке. Она обязана открыться сразу. Это и есть
   проверка того, что разрешение на ссылку закрепилось.
4. **Перезагрузить телефон** и повторить пункт 3: закреплённое
   разрешение обязано пережить и это.
5. **Файл пропал — книга ждёт.** Переименовать книгу в файловом
   менеджере и открыть её из приложения: должно появиться «до файла не
   добраться» и кнопка «Выбрать файл заново». Вернуть имя, нажать
   кнопку, выбрать файл — книга откроется **на том же месте**, где её
   оставили.
6. **Место на диске.** Настройки Android → Приложения → Memoria →
   Хранилище. После открытия крупной книги размер приложения расти не
   должен: копии больше нет.
7. **Книга с Google Диска** (если такая есть). Выбрать книгу из
   облачного хранилища: она должна открыться. Это тот случай, когда
   копия делается намеренно, и размер приложения тут вырасти обязан.

## Проверка владельцем после S4.7 (15 минут, телефон)

Ставить **v0.4.7-alpha** — или «Свежую сборку из main». Старую версию
перед установкой удалить: сборки подписаны одноразовым отладочным ключом
раннера, и Android не обновляет приложение чужим ключом.

1. **Дроби.** Открыть книгу, нажать в середину — в верхней панели левее
   поворота стоят ½ и ⅓. Нажать ½: экран поворачивается, страница делится
   пополам, кнопка подсвечена. Нажать ½ ещё раз — страница целиком.
   Нажать ⅓ из половины — сразу треть, без возврата.
2. **Затемнение.** В половине или трети отпереть замок (кнопка рядом с
   поворотом) и **сжать страницу пальцами**. Должна показаться вся
   страница: читаемая полоса светлая, остальное — в тени. Сила тени
   правится ползунком «Затемнение» в панели настроек; ноль гасить
   перестаёт.
3. **Замок.** Заперт — щипок и перетаскивание не делают ничего вовсе.
   Отперт — страница двигается и масштабируется и **остаётся** такой
   после того, как убрали пальцы, и после перелистывания. Запереть
   замок при увеличенной странице: масштаб обязан сохраниться.
4. **Строки на границе** (проверялось в S4.6, но затемнение трогало
   раскладку). Половина и треть: перелистнуть десяток экранов — ни одна
   строка не должна пропасть.
5. **Поиск переехал вниз.** Кнопка поиска теперь в нижней панели, рядом
   с оглавлением. Проверить, что заголовок книги наверху виден целиком,
   а не съеден кнопками.
6. **Настройки книги переживают перезапуск.** Закрыть приложение и
   открыть ту же книгу: режим, затемнение, запас и фильтр должны быть
   теми же. Здесь же молча отрабатывает миграция базы 2 → 3 — если
   что-то пойдёт не так, заметно будет именно тут.

<details>
<summary>Прошлая формулировка S5.1</summary>

**S5.1 — приём файла без копирования.** Идёт двумя шагами, и первый
ценен сам по себе (решение владельца, 23.08.2026).

**Шаг 1 — убрать падение.** Пикер меняется на `fast_file_picker`: он
сделан поверх того же `file_selector`, но файл при выборе не читает
вовсе — отдаёт имя и ссылку. Падение исчезает у источника, на файлах
любого размера. Дальше книга переносится в приложение потоковым
копированием на нативной стороне (`saf_stream.copyToLocalFile`). Цена
шага — файл занимает место дважды; читать книги при этом уже можно.

**Шаг 2 — убрать и копирование.** Свой мини-плагин на Android:
закреплённое разрешение на ссылку (книга открывается и через месяц, и
после перезагрузки), `openFileDescriptor` и номер дескриптора в Dart
через `detachFd()`. Читает `PdfDocument.openCustom` из pdfrx — у него
честный произвольный доступ через колбэк `read(buffer, position, size)`,
а сам колбэк зовёт `pread` из libc напрямую через FFI, без переходов
через канал на каждое чтение. Тем же приёмом открывают `content://`
нативные просмотрщики на PDFium. Лишнего места ноль, импорт мгновенный.
Потоковая копия остаётся запасным путём для облачных провайдеров, чья
ссылка не годится для перескоков. На Windows `file_selector` остаётся:
там настоящий путь и посредники не нужны.

Потерянное разрешение (файл переименовали, унесли карту памяти,
очистили данные) — не падение, а понятное состояние «файл недоступен,
выберите заново»: позиция чтения, цитаты и заметки принадлежат книге, а
не пути, и перевыбор файла их не теряет.

**Запасной вариант, записанный заранее.** Если и по дескриптору выйдет
плохо — медленно на больших книгах или ненадёжно из-за теряющихся
ссылок, — проект переходит на «Доступ ко всем файлам»
(`MANAGE_EXTERNAL_STORAGE`) и настоящие пути, как читалки с полкой на
тысячи книг. Это последний рубеж, а не первый: приложение, которое
продаёт приватность, просит такой доступ только когда иначе нельзя.

Автотесты: выбор пути (дескриптор или копия) на подставном источнике,
потоковое копирование на файле заметно больше буфера, поведение при
отозванном разрешении, корпус-тест «книга открывается через
`openCustom` так же, как по пути».

От владельца в конце S5.1 — 15 минут: открыть ту самую книгу на 73 МБ и
ещё пару крупных; оценить, быстро ли листается; закрыть и открыть
приложение заново — книга должна открываться без повторного выбора
файла. Если листание тормозит — это ответ про шаг 2, и он важнее
всего остального.

</details>

<summary>Прошлая формулировка S4</summary>

**S4 — читательская рамка.** Сердце миссии проекта: страница во весь
экран (автообрезка полей по координатам текста, для сканов — попиксельно,
опция «игнорировать колонтитулы», ручная правка рамки на всю книгу),
режимы отображения (страница / половина / треть / разворот, для
двухколоночных документов деление по колонкам) и светофильтры шейдером
поверх страницы (ночной красный монохром, тёплый, сепия, инверсия с
двойной инверсией картинок, затемнение ниже системного минимума, контраст
и гамма для бледных сканов). Обрезанная область рендерится **в разрешении
экрана**, а не растягивается из готовой картинки. Слой данных для всего
этого готов с S2, корпус PDF — с S3.

От владельца в конце S4 — 30 минут и самая важная ручная проверка
проекта: насколько крупнее стал текст в режиме половины, не режет ли
обрезка буквы, читаемо ли ночью с красным фильтром при выключенном свете.

**S3 — ядро читалки.** Интеграция pdfrx: открытие, листание постранично

корпуса «открыть → извлечь текст → отрендерить страницу». От владельца
в конце — 15 минут на телефоне и ПК: плавность листания, жесты
масштабирования, поведение на самом большом реальном PDF.
