### Что изменилось после перехода в open source

**CI перестал быть узким местом.** Публичный репозиторий получает безлимитные минуты GitHub Actions, включая Windows-раннеры, — двухуровневая экономная схема отменена, обе платформы собираются на каждый push.

**Отказ от Google Play Services.** Вход через Google делается браузерным потоком OAuth с PKCE, одинаково на Android и Windows. Это условие попадания в F-Droid, работа на телефонах без сервисов Google и один код OAuth вместо двух платформенных. Пакет `google_sign_in` из плана вычеркнут.

**Защита прокси при открытом коде.** Ключ провайдера LLM живёт в секретах Cloudflare, официальные сборки получают отзываемый токен доступа к прокси из GitHub Secrets через `--dart-define`. Плюс режим «свой API-ключ» для энтузиастов — уместен именно в открытом проекте и снимает нагрузку с общего прокси. Проверки Play Integrity не будет (она требует Play); её заменяют лимит на устройство в Workers KV и жёсткий дневной потолок.

**Лицензия GPL-3.0** — форки остаются открытыми, с MIT-лицензией pdfrx совместимо. Сменить на MIT легко, пока автор один, и почти невозможно после появления сторонних контрибьюторов: если нужна MIT — сказать до конца S1.

### Новое в плане: комфорт чтения (сессия S4)

Добавлена отдельная сессия **S4 «Читательская рамка»** — и это, по сути, главная функция продукта, а не полировка:

**Страница во весь экран.** Автоматическая обрезка белых полей (по координатам текстового слоя, для сканов — попиксельно), опция «игнорировать колонтитулы», ручная правка рамки с применением ко всей книге. Обрезанная область рендерится **в разрешении экрана**, а не растягивается из готовой картинки, иначе мелкий шрифт мылится.

**Режимы отображения:** страница целиком / половина страницы / разворот из двух страниц, плюс бесплатно получающаяся треть. Для двухколоночных PDF деление идёт по колонкам, а не по горизонтали. Режим запоминается для каждой книги и для каждой ориентации экрана. Смысл режима половины: кегль вырастает вдвое **без изменения вёрстки** — то, чего не может ни бумага, ни переформатируемый текст.

**Светофильтры** шейдером поверх страницы: ночной красный монохром с регулировкой, тёплый (снижение синего), сепия, инверсия с двойной инверсией картинок (иначе фотографии станут негативами), затемнение ниже системного минимума яркости, контраст и гамма для бледных сканов.

**Тема по умолчанию — тёмно-красная** (фон `#0E0708`, акцент `#A32F35`, текст `#E8DCD8`), вводится сразу в S1, чтобы весь UI строился в правильной палитре. Контраст каждой темы проверяется автотестом на WCAG AA: тёмно-красные схемы очень легко сделать красивыми и нечитаемыми.

Из-за вставки S4 сессии сдвинулись: библиотека теперь S5, выделение текста S6, Worker S7, облачная LLM S8, локальная LLM S9, CRDT S10, синхронизация S11, полировка S12, релиз S13.

### S1 — Каркас, открытая обвязка, CI (04.08.2026)

**Приложение.** Каркас Flutter со слоями `ui / application / domain / infrastructure`
и строгим `analysis_options.yaml` (`flutter analyze --fatal-infos --fatal-warnings`,
проверка `dart format` в CI). Навигация-заглушка: «Библиотека» и «Настройки».

**Темы.** Пять палитр, тёмно-красная по умолчанию. Цвета живут в `domain`
целыми числами ARGB — доменный слой не зависит от Flutter, перевод в `Color`
происходит на границе интерфейса в `ui/theme/theme_builder.dart`. Благодаря
этому контраст проверяется обычным юнит-тестом.

Контраст (WCAG 2.1) для каждой темы: основной и вторичный текст на фоне и на
поверхности — не ниже 4.5:1, подпись на акцентной заливке — не ниже 4.5:1,
нажатый акцент — не ниже 3.0:1. Худшее значение по всем темам — 4.74:1
(акцентный текст на поверхности тёмно-красной темы).

Опорный акцент `#A32F35` даёт к фону только 2.86:1, поэтому в палитре он
отвечает **только за заливку**, а для акцентного текста и иконок введён
отдельный, более светлый `accentText` (`#D2565B` в тёмно-красной теме).
Так фирменный цвет сохранён без потери читаемости.

**Обвязка.** README (миссия, приватность, сборка из исходников, структура),
CONTRIBUTING, CODE_OF_CONDUCT (Contributor Covenant 2.1), шаблоны issue
и PR, `.gitignore` с секретами и ключами подписи.

**CI.** `ci.yml` на каждый push: форматирование → анализ → тесты → APK
(ubuntu) → Windows и MSIX (windows-раннер), артефакты выкладываются.
`release.yml` по тегу `v*` собирает APK, AAB, портативный ZIP и MSIX
и создаёт черновик GitHub Release.

**Альфа-релиз.** Тег `v0.1.0-alpha.1` — первая сборка, которую можно
поставить руками: https://github.com/Owner102007/MemoriaLLM/releases/tag/v0.1.0-alpha.1

Артефакты прогона CI качаются **только с входом в аккаунт** и приходят
ZIP-архивом — на телефон так не поставить. Релизные ассеты качаются прямой
ссылкой без авторизации, поэтому `release.yml` публикует релиз сразу, а не
черновиком; тег с дефисом уходит предварительным релизом. В релиз кладутся
только APK и портативный ZIP: AAB нужен магазинам, MSIX подписан
заглушечными данными Partner Center — оба остаются артефактами прогона.

APK весит 42 МБ, потому что несёт все ABI сразу. Уменьшается через
`--split-per-abi`; отложено до S13, чтобы не плодить файлы до появления
настоящей подписи.

### Решения и находки S1

**У сессии нет Flutter SDK.** Сеть контейнера пропускает только `github.com`,
npm и PyPI; `storage.googleapis.com` (SDK и Dart) и `pub.dev` закрыты.
Поэтому анализ, тесты и сборки идут **только через CI** — это не временное
неудобство, а рабочая схема на весь проект. Соответствующий раздел
`CLAUDE.md` обновлён.

**Платформенные папки сгенерированы на раннере.** `android/` и `windows/`
создал workflow `bootstrap.yml` командой `flutter create` и закоммитил
в репозиторий; после этого он снят с триггера push и остаётся только
на ручной запуск. Писать эти папки руками было бы дорого и ненадёжно.

**Внутренние документы не публикуются.** Решение владельца от 04.08.2026:
`dev_plan_sessions.md`, `strategy_pdf_reader.md` и `SETUP.md` остаются
в папке `docs/` рядом с репозиторием. В SETUP.md есть незаполненные поля
под адреса и идентификаторы аккаунтов — именно в такой файл однажды
случайно впишут лишнее.

**Выбор темы пока не сохраняется** между запусками: слой данных появляется
в S2, тогда же тема переедет в настройки на диске.

**Читать результаты CI из сессии больно.** Логи прогона GitHub отдаёт
только авторизованным, а `api.github.com` закрыт прокси контейнера. Сводка
прогона (`$GITHUB_STEP_SUMMARY`) тоже видна лишь авторизованным — проверено.
Работают **аннотации**: их видно анонимно на странице прогона. Поэтому CI
при падении дублирует хвост вывода форматирования, анализа и тестов
аннотацией `::error::`, а полную сводку пишет для владельца.

**`dart format` и `require_trailing_commas` конфликтуют.** Форматер
переносит длинный вызов на новую строку, не добавляя хвостовую запятую,
а линтер при `--fatal-infos` считает это ошибкой. Лечится многострочной
формой вызова с запятой — она устойчива к обоим.

**Заглушки для Microsoft Store.** `identity_name` и `publisher` в
`msix_config` — временные значения до регистрации в Partner Center (S13).

## Известные риски и решения по ним

| Риск | Решение |
|---|---|
| Установка APK «из неизвестных источников» отпугнёт часть аудитории | Инструкция на странице проекта, Obtainium для автообновлений, IzzyOnDroid и RuStore как привычные каталоги |
| Обязательная верификация Android-разработчиков (пилот с 30.09.2026, глобально в 2027) затронет и сайдлоад | Отслеживать; при необходимости пройти верификацию в Android Developer Console |
| Автообрезка полей ошибётся на нетипичном макете | Ручная правка рамки + корпус проблемных PDF в тестах |
| Красная тема окажется нечитаемой | Автотест контраста WCAG AA + четыре альтернативные темы из коробки |
| Мелкий шрифт останется мылом при увеличении | Рендер обрезанной области в разрешении экрана, а не растяжение растра — заложено в постановку S4 |
| Злоупотребление прокси при открытом коде | Токен сборки из GitHub Secrets, лимит на устройство, дневной потолок, режим «свой ключ» |
| Бесплатный тир Gemini обучается на данных пользователей | Не использовать. Groq + локальная модель по умолчанию для чувствительного текста |
| Потеря релизного ключа Android делает обновление невозможным | Резервная копия keystore сразу при создании в S13 |
