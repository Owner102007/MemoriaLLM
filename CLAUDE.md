# CLAUDE.md — правила проекта «Memoria LLM HB»

*Этот файл читается первым в каждой сессии. Он описывает неизменные решения и рабочий процесс. Текущее состояние работ — в `PROGRESS.md`.*

*План сессий (`dev_plan_sessions.md`), обоснование решений (`strategy_pdf_reader.md`) и чек-лист регистраций владельца (`SETUP.md`) — внутренние документы: они лежат в папке `docs/` рядом с репозиторием и намеренно не публикуются.*

## Что это за проект

**Memoria LLM HB** — открытая кроссплатформенная читалка PDF (Android + Windows), продукт экосистемы «Библиотека ХохлоБарона».

**Миссия: вернуть электронной книге свойства бумажной и превзойти их.** Это не лозунг, а критерий приёмки решений. Страница занимает весь экран, а не окно в интерфейсе. Вёрстка неизменна — поэтому основа именно PDF, а не переформатируемый текст. Экран не бьёт в глаза. Читатель чувствует, сколько прочитано. Ничто не отвлекает. А сверх бумаги: мгновенное объяснение слова и контекстный перевод по выделению (**Meaning** / **Translate**), масштаб под любое зрение без слома вёрстки, чтение в темноте с красным светом, поиск, заметки и цитаты, одна и та же страница на всех устройствах.

Ограничения, которым подчинены все решения: **дёшево в эксплуатации** (инфраструктура — единицы долларов в месяц при тысячах пользователей), **просто и надёжно** (минимум движущихся частей), **всё что можно — на устройстве пользователя**.

Проект **открытый**: код публичен, лицензия **GPL-3.0**. Отсюда три постоянных требования: приложение не должно делать ничего, чего нельзя показать в исходниках; секреты не могут жить в коде; README и CONTRIBUTING поддерживаются в актуальном состоянии наравне с кодом.

## Стек и архитектурные решения (пересмотру не подлежат без явного запроса владельца)

| Область | Решение |
|---|---|
| Фреймворк | Flutter, одна кодовая база Android + Windows |
| PDF | `pdfrx` (MIT, движок PDFium): рендер, выделение текста с координатами, извлечение текста, обложки |
| Чтение | Собственный слой «читательской рамки» поверх pdfrx: автообрезка полей, режимы страница / половина / треть / разворот, светофильтры шейдером |
| БД | SQLite через `drift`; поверх — `sqlite_crdt` для слияния |
| Локальная LLM | `flutter_gemma`; Gemma 3 1B int4 (~530 МБ), опционально Qwen 3 1.7B; **скачивается по запросу, не вшивается в сборку** |
| Облачная LLM | Через свой прокси. Основной провайдер — **Groq** (бесплатный тир); резерв — платный Gemini 2.5 Flash-Lite и Llama 8B на DeepInfra. **Бесплатный тир Gemini запрещён**: Google обучается на содержимом запросов |
| Прокси LLM | Cloudflare Worker (бесплатный тир): прячет ключ, лимитирует по устройству, роутит провайдеров |
| Синхронизация | **Google Drive appDataFolder самого пользователя**. Своей БД у проекта нет и не будет |
| Авторизация | Вход через Google **браузерным потоком OAuth с PKCE, одинаково на обеих платформах**. Пакет `google_sign_in` и любые зависимости от Google Play Services запрещены |
| Крэш-репортинг | Sentry |

**Почему appDataFolder, а не свой сервер**: данные лежат в облаке пользователя и расходуют его квоту — наши расходы на хранение равны нулю при любом числе пользователей. Скоуп `drive.appdata` — non-sensitive, поэтому не нужны ни CASA, ни демо-видео, ни лимит в 100 пользователей.

**Почему без Google Play Services**: открытый проект должен собираться из исходников без проприетарных зависимостей (условие F-Droid) и работать на телефонах без сервисов Google. Побочная выгода — один код OAuth вместо двух платформенных.

**Почему модель не в сборке**: раздутый установщик убивает установки, а модель нужна не всем — приложение полностью работает через облако.

## Релизы

**Каждая сессия заканчивается релизом.** Номер версии — номер сессии
в минорной позиции: S2 → `v0.2.0-alpha`, S3 → `v0.3.0-alpha`, и так до
`v1.0.0` на S13. Версия правится в `pubspec.yaml` (`version` и
`msix_version`), тег ставится последним действием сессии, после зелёного
CI. Тег с дефисом уходит предварительным релизом.

Параллельно живёт **катящийся релиз `latest`**: CI обновляет его после
каждого зелёного прогона в `main`, имена файлов постоянные, поэтому
ссылки не меняются никогда:

- `releases/download/latest/memoria.apk`
- `releases/download/latest/memoria-windows.zip`

Он предварительный и помечен `make_latest: false`, чтобы не подменять
собой релизы этапов. Артефакты прогона остаются, но качать из них
неудобно: они отдаются только авторизованным и приходят ZIP-архивом.

## Дистрибуция

Google Play **отменён** (регистрация требует карты, которая не проходит). Каналы: Android — GitHub Releases (основной, плюс Obtainium для автообновлений), IzzyOnDroid, F-Droid, RuStore. Windows — Microsoft Store (MSIX подписывает Microsoft бесплатно) и портативный ZIP в релизах. Сборка `.aab` в CI сохраняется на случай появления Play в будущем.

## Структура репозитория

```
lib/
  ui/               экраны и виджеты
  application/      сценарии: открыть книгу, спросить LLM, синхронизировать
  domain/           чистые модели и правила (без внешних зависимостей — легко тестируется);
                    здесь же геометрия читательской рамки
  infrastructure/   pdfrx, drift, flutter_gemma, Drive API, HTTP
shaders/            фрагментные шейдеры светофильтров
test/
  fixtures/         корпус проблемных PDF (сканы, CJK, RTL, битые, огромные, двухколоночные)
worker/             код Cloudflare Worker + его тесты
```

Зависимость направлена внутрь: `ui → application → domain`; `infrastructure` реализует интерфейсы, объявленные в `domain`. Платформенные различия (пути, файловый пикер) прячутся за интерфейсами — общего кода должно оставаться ~90 %.

## Правила работы в сессии

1. **Начало сессии**: прочитать `CLAUDE.md` и `PROGRESS.md`, свериться с планом сессий, объявить цель одной строкой.
2. **Одна сессия — одна задача из плана.** Не расползаться в соседние сессии, даже если «уже почти».
3. **Каждый баг сначала воспроизводится тестом**, потом чинится. Регрессионный тест остаётся в репозитории.
4. **Ничего не мержится в `main` при красном CI.** Зелёный CI на обеих платформах — критерий завершения сессии.
5. **Секреты не хардкодятся никогда.** Только GitHub Secrets, секреты Worker'а и локальный `.env` (в `.gitignore`). В открытом репозитории это не формальность: утёкший ключ виден всему миру за минуты. Если секрет попал в коммит — сказать владельцу немедленно, ключ отзывается.
6. **Изящная деградация — правило проектирования, а не опция.** Нет сети → локальная модель; нет модели → понятное предложение скачать; PDF без текстового слоя → честное сообщение при импорте; конфликт синхронизации → слияние, а не потеря данных.
7. **Комфорт чтения — не «полировка», а функция первого класса.** Любое изменение в читалке проверяется вопросом: страница по-прежнему занимает весь экран, вёрстка не поехала, глазам не хуже?
8. **Конец сессии**: обновить `PROGRESS.md` (сделано / решения / известные проблемы / что дальше) и выдать владельцу **отдельным блоком** чек-лист ручных проверок — только то, что невозможно автоматизировать.

## Оформление и темы

Тема по умолчанию — **тёмно-красная** (часть визуального языка экосистемы). Опорная палитра: фон `#0E0708`, поверхность `#170D0F`, разделители `#2A1619`, акцент `#A32F35`, акцент нажатия `#C7454A`, текст `#E8DCD8`, текст вторичный `#B9A6A2`. Дополнительно: ночная красная (монохром), нейтральная тёмная, сепия, светлая. **Контраст основного текста к фону — не ниже 4.5:1, проверяется автотестом** для каждой темы: тёмно-красные схемы очень легко сделать красивыми и нечитаемыми.

## Что владелец делает руками (и только это)

Аккаунты и секреты; проверки на живых устройствах (комфорт чтения и режимы отображения, жесты, плавность, качество ответов LLM на его книгах, синхронизация телефон↔ПК); ключ подписи Android и его резервная копия; формы каталогов и публикация релизов. Всё остальное — код, тесты, корпуса данных, CI, шейдеры, промпты, деплой, тексты, скриншоты — делает сессия.

## Тестирование

Плотно покрываем то, где живут баги: **геометрия читательской рамки** (обрезка полей на всём корпусе, деление на 2 и 3, определение колонок, сохранение позиции при смене режима — чистая математика, тестируется исчерпывающе), логика слияния CRDT (коммутативность, идемпотентность, симуляция двух расходящихся устройств), извлечение текста и контекста из PDF на корпусе `test/fixtures`, роутер LLM (таймауты, 429, обрыв стрима, фолбэки), загрузчик модели. UI — widget-тестами ключевых экранов, golden-тестами карточек библиотеки и **каждого светофильтра**. Контраст тем — автотестом. Не тестируем чужой код: рендеринг PDFium и качество самих моделей.

CI — GitHub Actions. Репозиторий **публичный, поэтому минуты не считаются**, включая windows-раннеры. На каждый push в любую ветку: `flutter analyze` (строгий) → `flutter test` → сборка APK (ubuntu-раннер) → сборка Windows + MSIX (windows-раннер) → артефакты для скачивания владельцем. Отдельный workflow по тегу собирает релиз (APK, AAB, MSIX, портативный ZIP) и публикует GitHub Release.

Windows-раннер существует именно потому, что у сессии нет доступа к Windows — это её «руки». Критерий готовности неизменен: **зелено на обеих платформах**.

## Ограничения окружения сессии

Claude работает в Linux-контейнере, сеть которого пропускает только
`github.com`, npm и PyPI. **Flutter SDK поставить нельзя**: закрыты
`storage.googleapis.com` (сам SDK и Dart) и `pub.dev` (зависимости).
Практическое следствие: `flutter analyze`, `flutter test`, headless-прогон
корпуса PDF и любые сборки выполняются **только в CI** — сессия пишет код
и читает результаты прогонов на GitHub Actions.

Также недоступны: сборка и запуск под Windows, физический Android-телефон,
реальные аккаунты и консоли каталогов. Всё, что упирается в эти ограничения,
либо перекладывается на CI, либо попадает в чек-лист владельцу.

Платформенные папки `android/` и `windows/` сгенерированы на раннере
workflow'ом `.github/workflows/bootstrap.yml` (`flutter create`) и лежат
в репозитории; повторно он не запускается.

Сгенерированный код drift (`*.g.dart`) в репозитории **не хранится**:
сессия не может его пересобрать, а устаревший файл в коммите — источник
необъяснимых падений. Его собирает CI шагом `build_runner` перед анализом,
тестами и каждой сборкой.

Проверку формата CI делает так: сам прогоняет `dart format` и, если файлы
изменились, печатает готовый патч в лог и валит прогон. Без Dart SDK
сессия иначе не узнает, что именно поправить. Анализ и тесты после этого
идут по уже отформатированному коду — одна ошибка формата не съедает
целый прогон.

Push в GitHub зависит от режима запуска сессии: локально работает с токеном
из `_secrets/github_token.txt`, в облачной сессии прокси срезает токен и
отдаёт 403 — тогда push делает владелец.
