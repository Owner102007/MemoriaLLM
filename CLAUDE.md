# CLAUDE.md — правила проекта «Memoria LLM HB»

*Этот файл читается первым в каждой сессии. Он описывает неизменные решения и рабочий процесс. Текущее состояние работ — в `PROGRESS.md`.*

*План сессий (`dev_plan_sessions.md`), обоснование решений (`strategy_pdf_reader.md`) и чек-лист регистраций владельца (`SETUP.md`) — внутренние документы: они лежат в папке `docs/` рядом с репозиторием и намеренно не публикуются.*

---

## Что это за проект

**Memoria LLM HB** — открытая кроссплатформенная читалка PDF (Android + Windows), продукт экосистемы «Библиотека ХохлоБарона».

**Миссия: вернуть электронной книге свойства бумажной и превзойти их.** Это не лозунг, а критерий приёмки решений. Страница занимает весь экран, а не окно в интерфейсе. Вёрстка неизменна — поэтому основа именно PDF, а не переформатируемый текст. Экран не бьёт в глаза. Читатель чувствует, сколько прочитано. Ничто не отвлекает. А сверх бумаги: **свой вопрос к любому выделенному тексту** — объяснение слова, контекстный перевод, словарная статья, разбор грамматики: промпт пишет читатель, а Meaning и Translate идут из коробки как две готовые заготовки; масштаб под любое зрение без слома вёрстки, чтение в темноте с красным светом, поиск, заметки и цитаты, одна и та же страница на всех устройствах.

Ограничения, которым подчинены все решения: **дёшево в эксплуатации** (инфраструктура — единицы долларов в месяц при тысячах пользователей), **просто и надёжно** (минимум движущихся частей), **всё что можно — на устройстве пользователя**.

Проект **открытый**: код публичен, лицензия **GPL-3.0**. Отсюда три постоянных требования: приложение не должно делать ничего, чего нельзя показать в исходниках; секреты не могут жить в коде; README и CONTRIBUTING поддерживаются в актуальном состоянии наравне с кодом.

## Стек и архитектурные решения (пересмотру не подлежат без явного запроса владельца)

| Область | Решение |
|---|---|
| Фреймворк | Flutter, одна кодовая база Android + Windows |
| PDF | `pdfrx` (MIT, движок PDFium): рендер, выделение текста с координатами, извлечение текста, обложки |
| Чтение | Собственный слой «читательской рамки» поверх pdfrx: автообрезка полей, режимы страница / половина / треть / разворот, светофильтры шейдером. **Деление одинаково во всех книгах — страница режется поперёк на 2 или 3 полосы, вёрстка на это не влияет** (решение владельца, 23.08.2026): дробь на кнопке значит ровно то, что нарисована. **Положение экрана выбирается по форме области показа**, а не по названию режима: режим не имеет права уменьшить кегль, а если выигрыша нет — не включается молча. С S4.1 полоса **прижимается к верхнему краю, а не центрируется**, и показывается с **нахлёстом** (в процентах экрана, не страницы; по умолчанию 7 %, при делителе 3 вдвое меньше, потолок 15 %); перекрытая часть затемняется. Полоса содержимого при этом остаётся ровно 1/N, а прогресс считается по чистой доле, а не по окну с нахлёстом |
| Управление чтением | Перелистывание кнопками громкости на Android (`dispatchKeyEvent` в `MainActivity` + канал): долгое удержание не перехватывается и меняет громкость; при активном экранном дикторе перехват не включается вовсе; шаг — полоса, а не страница. На Windows ту же роль играют пробел, PgUp/PgDn и стрелки с настраиваемым соответствием клавиш. Побочно поддерживаются bluetooth-«листалки» — они шлют те же коды |
| БД | SQLite через `drift`; поверх — `sqlite_crdt` для слияния |
| Локальная LLM | `flutter_gemma`; Gemma 3 1B int4 (~530 МБ), опционально Qwen 3 1.7B; **скачивается по запросу, не вшивается в сборку** |
| Облачная LLM | Через свой прокси. Основной провайдер — **Groq** (бесплатный тир); резерв — платный Gemini 2.5 Flash-Lite и Llama 8B на DeepInfra. **Бесплатный тир Gemini запрещён**: Google обучается на содержимом запросов |
| Прокси LLM | Cloudflare Worker (бесплатный тир): прячет ключ, лимитирует по устройству, роутит провайдеров |
| Доступ к файлам | Книга **не копируется в приложение** (сделано в S5.1). Место книги описывает `BookSource`: путь, ссылка `content://` или наша копия. Android с S5.4 — **«Доступ ко всем файлам» основным путём** (решение владельца, 05.09.2026): `MANAGE_EXTERNAL_STORAGE` на 11+, `READ_EXTERNAL_STORAGE` ниже; книги находятся сканером и живут по настоящим путям. Доступ нужен, чтобы книгу **найти**, а не забрать: копирование через память запрещено по-прежнему. Отказ в разрешении не ломает ничего — приложение работает по пути S5.1: `fast_file_picker`, закреплённое разрешение на ссылку (~25 строк Kotlin в `MainActivity`), дескриптор от `saf_util`, `PdfDocument.openCustom` и FFI-`pread`, потоковый перенос для непригодных к перескокам ссылок. Этот путь деградации обязателен и покрыт тестами наравне с основным. Windows: обычный путь |
| Книги на устройстве | Экран обзора вместо системного диалога (S5.4): сканер в изоляте (`.pdf` по расширению **и** сигнатуре `%PDF-`, пропуск `Android/data`, `Android/obb`, скрытых папок и кешей), склейка дубликатов по отпечатку, обложки только у видимых карточек. Поиск — три ступени: имя файла → метаданные PDF → текст первых 3–5 непустых страниц; индекс SQLite FTS5, `bm25`, нормализация с `ё`/`е` и **свёрткой латинских гомоглифов в кириллице**. Пересказ моделью для поиска **не делается**: индекс, а не пересказ (решение владельца, 05.09.2026) |
| Верстак PDF | Резка и склейка средствами `pdfrx_engine` (уже в зависимостях, чистый Dart — проверяется на Linux-раннере): `createNew` → список страниц → `encodePdf`. **Исходники не изменяются никогда**, результат — новый файл потоком на диск. Склейка вешается на **задержку книги над обложкой**, а не на отпускание: обычное перетаскивание на полке остаётся перестановкой |
| Полка | Книги лежат в **категориях**: одна книга — одна категория, «Без категории» — постоянный раздел наверху. Категория растёт блоками: блок = книга, три блока в строке на телефоне, больше на широком окне ПК при том же размере блока; кнопка «+» — последний блок. Узор и цвет подложки **выводятся из названия** категории (`domain/library/category_style.dart`), выбирать их вручную нельзя: одинаковый вид на всех устройствах дороже настройки (решение владельца, 24.08.2026) |
| Вид категории | Узоры **абстрактные и машинные** — сетки, трассы, потоки данных, сбои развёртки; шестнадцать узоров на восемнадцать оттенков (решение владельца, 28.08.2026). Основной строй — тёмные оттенки; примерно **одна категория из семи** выходит кислотной и светится неоном. Потолок громкости держится не цветом, а тем, сколько его: неон рисуется тонкой линией, и вес участка (средний цвет подложки под узором) не уходит от подложки дальше чем втрое по контрасту. На светлых темах кислота приглушается до обычной фактуры: неон на бумажном фоне читается как маркер, а не как свечение |
| Перестановка книг | Книга берётся долгим нажатием на телефоне и сразу мышью на ПК; кладётся между любыми двумя книгами своей или чужой категории. Первый же перенос переводит полку в ручной порядок «Как расставил» — иначе сортировка вернула бы книгу на место в тот же миг. Место — **дробное число между соседями** (правится только у перенесённого элемента): целые номера с перенумерацией всей категории не переживают слияния CRDT, два офлайновых устройства отдали бы два несовместимых набора (решение владельца, 05.09.2026). Перенумерация остаётся редкой операцией уплотнения. Расстановка **синхронизируется** наравне с цитатами. У краёв экрана полка едет сама, и зон **две**: у самого края быстро, чуть дальше медленно (`domain/library/drag_scroll.dart`). Расчёт один и тот же на телефоне и на ПК |
| Перестановка категорий | Категория берётся **только за шапку** (иначе жест спорит с перетаскиванием книг) и на время переноса сворачивается в узкую полосу. «Без категории» закреплена наверху: места ей не назначается, транзакция перенумерации её пропускает. Позиции дробные, как у книг |
| Обложки | Первая страница книги, отрисованная PDFium и упакованная **своим** кодировщиком PNG; кэш на диске по отпечатку книги, очередь на две книги за раз, упаковка — в фоновом изоляте |
| Выделение | Слой выделения (`PdfViewer` над листом) монтируется **заранее и невидимо**, а жест лишь делает его видимым: виджет, созданный в момент касания, успевает моргнуть (решение по проверке 06.09.2026). Жест-стартер зависит от указателя: на ПК — протяжка мышью, сразу, без ожидания; на телефоне — долгое нажатие с порогом около 250 мс. **Листание работает и при выделенном тексте**: зоны и клавиши не перекрываются слоем, переход на другую страницу снимает выделение |
| Полотно | Заметки и разговор с моделью живут **плавающими окнами над страницей** (решение владельца, 06.09.2026; образец — холст Obsidian): перенос, изменение размера, свёртка в ярлык, закрытие, порядок наложения — одинаково пальцем и мышью. Цвет окна заметки совпадает с цветом подсветки её текста: по цвету видно, какая заметка о чём. Заметка привязана к месту и уходит вместе со своей страницей; окно разговора остаётся на экране, пока его не закрыли. Геометрия хранится **долями страницы** и **не синхронизируется** — окно про экран, а не про книгу |
| Вопрос к выделению | Промпт пишет **читатель**, а не мы за него (решение владельца, 06.09.2026). До пяти именованных промптов, каждый — своя кнопка в панели над выделением, один основной. Meaning и Translate заводятся из коробки как две записи, которые можно править, переименовать и удалить, — а не как код. Места подстановки: `{{выделение}}` (обязательное), `{{контекст}}`, `{{язык_книги}}`, `{{мой_язык}}`; без `{{контекст}}` абзац не извлекается вовсе. Два уровня, как у настроек отображения: мастер-набор и поправка для книги, правится прямо в чтении |
| Синхронизация | **Google Drive appDataFolder самого пользователя**. Своей БД у проекта нет и не будет. В облако уходит **только прогресс чтения и то, что читатель создал сам** — цитаты, заметки, закладки, расстановка полки (порядок книг и категорий: его создал читатель, решение владельца 05.09.2026), **цвет и привязка заметок** и **промпты к выделению обоих уровней** (решение владельца, 06.09.2026: промпт — это текст, который читатель сочинил, ровно как заметка; переписывать его на втором устройстве — работа, которой быть не должно). Поэтому промптам нужна своя синхронизируемая таблица: `app_settings` намеренно без полей CRDT. Список файлов устройства и индекс поиска не уходят никуда |
| Настройки отображения | Два уровня, **оба на устройстве**: мастер-настройки (какой открывается любая книга) и настройки книги (поправка к ним, предлагается сразу после открытия). Между устройствами переносятся по явной кнопке, а не сами: удобное на телефоне почти никогда не удобно на большом экране. Промпты к выделению устроены так же двухуровнево, но под это правило **не подпадают** и синхронизируются — они не про экран. Светофильтр по умолчанию выбирается **сам, по времени суток**: утром светлый, днём сепия, вечером красный |
| Авторизация | Вход через Google **браузерным потоком OAuth с PKCE, одинаково на обеих платформах**. Пакет `google_sign_in` и любые зависимости от Google Play Services запрещены |
| Крэш-репортинг | Sentry |

**Почему appDataFolder, а не свой сервер**: данные лежат в облаке пользователя и расходуют его квоту — наши расходы на хранение равны нулю при любом числе пользователей. Скоуп `drive.appdata` — non-sensitive, поэтому не нужны ни CASA, ни демо-видео, ни лимит в 100 пользователей.

**Почему без Google Play Services**: открытый проект должен собираться из исходников без проприетарных зависимостей (условие F-Droid) и работать на телефонах без сервисов Google. Побочная выгода — один код OAuth вместо двух платформенных.

**Почему модель не в сборке**: раздутый установщик убивает установки, а модель нужна не всем — приложение полностью работает через облако.

**Windows — не уменьшенная копия Android** (решение владельца, 23.08.2026). На ПК несколько книг открыты сразу во вкладках, ориентации экрана нет вовсе, а размер окна меняет человек в любой момент: раскладка при этом **пересчитывается, а страница перерисовывается** под новый размер, а не растягивается из готового растра. Форма окна на ПК играет ту же роль, что положение экрана на телефоне, и подаётся в ту же математику деления.

## Релизы

**Каждая сессия заканчивается релизом.** Номер версии — номер сессии
в минорной позиции: S2 → `v0.2.0-alpha`, S3 → `v0.3.0-alpha`, и так до
`v1.0.0` на S13. Версия правится в `pubspec.yaml` (`version` и
`msix_version`), тег ставится последним действием сессии, после зелёного
CI. Тег с дефисом уходит предварительным релизом.

Параллельно живёт **катящийся релиз `latest`**: CI обновляет его после
каждого зелёного прогона в `main`, имена файлов постоянные, поэтому
ссылки не меняются никогда:

- `releases/download/latest/memoria.apk`
- `releases/download/latest/memoria-windows.zip`

Он предварительный и помечен `make_latest: false`, чтобы не подменять
собой релизы этапов. Артефакты прогона остаются, но качать из них
неудобно: они отдаются только авторизованным и приходят ZIP-архивом.

## Дистрибуция

Google Play **отменён** (регистрация требует карты, которая не проходит). Каналы: Android — GitHub Releases (основной, плюс Obtainium для автообновлений), IzzyOnDroid, F-Droid, RuStore. Windows — Microsoft Store (MSIX подписывает Microsoft бесплатно) и портативный ZIP в релизах. Сборка `.aab` в CI сохраняется на случай появления Play в будущем.

## Структура репозитория

```
lib/
  ui/               экраны и виджеты (полка — ui/library)
  application/      сценарии: открыть книгу, спросить LLM, синхронизировать
  domain/           чистые модели и правила (без внешних зависимостей — легко тестируется);
                    здесь же геометрия читательской рамки
  infrastructure/   pdfrx, drift, flutter_gemma, Drive API, HTTP
  infrastructure/images/  свой минимальный кодировщик PNG для обложек
shaders/            фрагментные шейдеры светофильтров
test/
  fixtures/         корпус проблемных PDF (сканы, CJK, RTL, битые, огромные, двухколоночные)
worker/             код Cloudflare Worker + его тесты
```

Зависимость направлена внутрь: `ui → application → domain`; `infrastructure` реализует интерфейсы, объявленные в `domain`. Платформенные различия (пути, файловый пикер) прячутся за интерфейсами — общего кода должно оставаться ~90 %.

## Правила работы в сессии

1. **Начало сессии**: прочитать `CLAUDE.md` и `PROGRESS.md`, свериться с планом сессий, объявить цель одной строкой.
2. **Одна сессия — одна задача из плана.** Не расползаться в соседние сессии, даже если «уже почти».
3. **Каждый баг сначала воспроизводится тестом**, потом чинится. Регрессионный тест остаётся в репозитории.
4. **Ничего не мержится в `main` при красном CI.** Зелёный CI на обеих платформах — критерий завершения сессии.
5. **Секреты не хардкодятся никогда.** Только GitHub Secrets, секреты Worker'а и локальный `.env` (в `.gitignore`). В открытом репозитории это не формальность: утёкший ключ виден всему миру за минуты. Если секрет попал в коммит — сказать владельцу немедленно, ключ отзывается.
6. **Изящная деградация — правило проектирования, а не опция.** Нет сети → локальная модель; нет модели → понятное предложение скачать; PDF без текстового слоя → честное сообщение при импорте; конфликт синхронизации → слияние, а не потеря данных.
7. **Комфорт чтения — не «полировка», а функция первого класса.** Любое изменение в читалке проверяется вопросом: страница по-прежнему занимает весь экран, вёрстка не поехала, глазам не хуже?
8. **Конец сессии**: обновить `PROGRESS.md` (сделано / решения / известные проблемы / что дальше) и выдать владельцу **отдельным блоком** чек-лист ручных проверок — только то, что невозможно автоматизировать.

## Оформление и темы

Тема по умолчанию — **тёмно-красная** (часть визуального языка экосистемы). Опорная палитра: фон `#0E0708`, поверхность `#170D0F`, разделители `#2A1619`, акцент `#A32F35`, акцент нажатия `#C7454A`, текст `#E8DCD8`, текст вторичный `#B9A6A2`. Дополнительно: ночная красная (монохром), нейтральная тёмная, сепия, светлая. **Контраст основного текста к фону — не ниже 4.5:1, проверяется автотестом** для каждой темы: тёмно-красные схемы очень легко сделать красивыми и нечитаемыми.

## Что владелец делает руками (и только это)

Аккаунты и секреты; проверки на живых устройствах (комфорт чтения и режимы отображения, жесты, плавность, качество ответов LLM на его книгах, синхронизация телефон↔ПК); ключ подписи Android и его резервная копия; формы каталогов и публикация релизов. Всё остальное — код, тесты, корпуса данных, CI, шейдеры, промпты, деплой, тексты, скриншоты — делает сессия.

## Тестирование

Плотно покрываем то, где живут баги: **геометрия читательской рамки** (обрезка полей на всём корпусе, деление на 2 и 3, определение колонок, сохранение позиции при смене режима — чистая математика, тестируется исчерпывающе), логика слияния CRDT (коммутативность, идемпотентность, симуляция двух расходящихся устройств), извлечение текста и контекста из PDF на корпусе `test/fixtures`, роутер LLM (таймауты, 429, обрыв стрима, фолбэки), загрузчик модели. геометрия полки (сколько блоков в строке, где стоит «+», порядок книг) и вид категории — тоже чистая математика: узор и цвет сверяются с эталонной таблицей, посчитанной **другой** реализацией, а контраст текста на подложке категории проверяется тем же порогом WCAG, что и темы. UI — widget-тестами ключевых экранов и golden-тестами **каждого светофильтра**. Контраст тем — автотестом. С правками 05.09.2026 добавляются: геометрия окна с нахлёстом и два инварианта, которые она способна тихо сломать («полоса содержимого равна 1/N при любом нахлёсте», «прогресс не зависит от нахлёста»); обход файловой системы на собранном в тесте дереве (служебные ветки, скрытые файлы, чужое расширение, `.pdf` без сигнатуры); нормализация и ранжирование поиска на корпусе запросов, включая латиницу в кириллице; **сценарий «разрешение не дано» целиком** — приложение обязано работать; резка и склейка PDF с проверкой результата обратным открытием и сверкой отпечатков исходников до и после. Не тестируем чужой код: рендеринг PDFium и качество самих моделей.

CI — GitHub Actions. Репозиторий **публичный, поэтому минуты не считаются**, включая windows-раннеры. На каждый push в любую ветку: `flutter analyze` (строгий) → `flutter test` → сборка APK (ubuntu-раннер) → сборка Windows + MSIX (windows-раннер) → артефакты для скачивания владельцем. Отдельный workflow по тегу собирает релиз (APK, AAB, MSIX, портативный ZIP) и публикует GitHub Release.

Windows-раннер существует именно потому, что у сессии нет доступа к Windows — это её «руки». Критерий готовности неизменен: **зелено на обеих платформах**.

## Ограничения окружения сессии

Claude работает в Linux-контейнере, сеть которого пропускает только
`github.com`, npm и PyPI. **Flutter SDK поставить нельзя**: закрыты
`storage.googleapis.com` (сам SDK и Dart) и `pub.dev` (зависимости).
Практическое следствие: `flutter analyze`, `flutter test`, headless-прогон
корпуса PDF и любые сборки выполняются **только в CI** — сессия пишет код
и читает результаты прогонов на GitHub Actions.

Также недоступны: сборка и запуск под Windows, физический Android-телефон,
реальные аккаунты и консоли каталогов. Всё, что упирается в эти ограничения,
либо перекладывается на CI, либо попадает в чек-лист владельцу.

Платформенные папки `android/` и `windows/` сгенерированы на раннере
workflow'ом `.github/workflows/bootstrap.yml` (`flutter create`) и лежат
в репозитории; повторно он не запускается.

Сгенерированный код drift (`*.g.dart`) в репозитории **не хранится**:
сессия не может его пересобрать, а устаревший файл в коммите — источник
необъяснимых падений. Его собирает CI шагом `build_runner` перед анализом,
тестами и каждой сборкой.

Проверку формата CI делает так: сам прогоняет `dart format` и, если файлы
изменились, печатает готовый патч в лог и валит прогон. Без Dart SDK
сессия иначе не узнает, что именно поправить. Анализ и тесты после этого
идут по уже отформатированному коду — одна ошибка формата не съедает
целый прогон.

Push в GitHub идёт с токеном из `_secrets/github_token.txt`. В файле два
вхождения `github_pat_`: первое (93 знака) — рабочий токен, второе
(усечённое) — упоминание отозванного в комментарии. Брать первое.

**Прокси токен не срезает.** Это записанное здесь прежде объяснение было
неверным и стоило целой итерации. Проверено 05.09.2026 через
`GIT_CURL_VERBOSE=1`: прокси поднимает обычный туннель `CONNECT`,
сертификат — настоящий гитхабовский (`server certificate verification OK`,
издатель Sectigo), значит, влезть в TLS и что-то поменять он не может.
Git честно шлёт `authorization: Basic`, а **401 приходит от самого
GitHub**. Отказ в пуше — это отказ токена, а не сети.

Как различить за одну команду:

```bash
GIT_CURL_VERBOSE=1 git push … 2>&1 | grep -i "certificate verification\|HTTP/2 4"
```

Нет заголовка `authorization` во втором запросе или чужой сертификат —
дело в сети. Заголовок ушёл, в ответ `HTTP/2 401` — дело в токене.

Быстрая проба живости токена — обращение к **несуществующему**
репозиторию (на публичном репозитории чтение проходит вообще без токена,
поэтому `git ls-remote` на самом MemoriaLLM не доказывает ничего):

```bash
GIT_TERMINAL_PROMPT=0 git ls-remote \
  "https://x-access-token:${TOKEN}@github.com/Owner102007/net-takogo-repo.git"
```

`Repository not found` — токен жив. `Invalid username or token` — токен
мёртв, и новый заводит владелец: сессия токенов не создаёт.

Три разных отказа, которые легко перепутать:

| Ответ | Что это значит |
|---|---|
| `401 Invalid username or token` | токен не принят вовсе: мёртв, отозван или испорчен |
| `403 Permission to … denied to <логин>` | токен принят, владелец опознан, но прав не хватает: у fine-grained токена не выбран этот репозиторий или не выдано **Contents: Read and write** |
| `Repository not found` на живом репозитории | то же самое, что 403, но GitHub прячет существование репозитория |

**Токен ставится только в позицию пароля**, `https://x-access-token:ТОКЕН@…`.
В позиции имени пользователя (`https://ТОКЕН@…`) git печатает его
открытым текстом в собственном сообщении об ошибке — «could not read
Password for 'https://<токен>@github.com'», — и секрет утекает в лог.
На этом уже обожглись 05.09.2026.

**Результаты CI читаются из ветки `ci-report`.** После каждого прогона
job `report` кладёт туда `report.md` — итог всех трёх задач и вывод
форматирования, кодогенерации, анализа и упавших тестов:

```bash
git fetch origin ci-report && git show origin/ci-report:report.md
```

Ветка сиротская и переписывается каждым прогоном: это не история, а
последнее состояние. Git из сессии работает всегда и ничего не кэширует.

Остальные пути хуже и оставлены на случай, если этот откажет. Расширение
Claude в Chrome под аккаунтом владельца отдаёт и сводку, и полный лог —
но подключено оно не в каждой сессии. Анонимные страницы GitHub не
годятся вовсе: они сильно закэшированы и показывают состояние
многодневной давности — из них уже дважды делался неверный вывод о том,
что происходит с CI. `api.github.com` закрыт прокси контейнера.

В локальном режиме git иногда не может удалить свой `.git/*.lock`
(«Operation not permitted» на смонтированной папке). Переименование внутри
той же папки при этом работает, поэтому лечится так: перед git-командой
переименовать `index.lock`, `HEAD.lock` и `refs/heads/main.lock` в
`stale-*`. Ошибка «Another git process seems to be running» — про это же.
