# Спутник взгляда (СНО2026)

Программа на Python, которая лежит рядом с приложением в ZIP ветвей
СНО2026 для Windows (`eye/` рядом с `memoria.exe`). Снимает веб-камеру,
находит ориентиры лица (MediaPipe), пишет признаки кадра
`features.bin` и полосу глаз `eyes.mp4`. Во время записи участника пишет ещё
поток взгляда `gaze.jsonl` — оценку точки взгляда моделью калибровки,
строку на кадр (`sno_eye/gaze.py`). Книг, журнала и экранов приложения
не знает. Схема — «Айтрекер — схема системы и план внедрения» в
описательной структуре; функции SNO-F-EYE-01…06, SNO-F-REC-04.

## Для организатора

* `Проверка камеры.cmd` — самопроверка места и две минуты замера.
  Пока идёт замер, откройте в приложении книгу и листайте её.
  Итог — `bench.json` в папке `eye\bench\<дата-время>\`.
* `Проверка камеры (40 минут).cmd` — то же на сорок минут.
* `Проверка записи.cmd` — перетащите на него архив записи
  `sno2026_….zip` или папку с архивами (и с телефонов тоже): по каждой
  записи — «годна», «с оговорками» или «не годна» и почему; рядом
  ложится таблица `проверка_записей.csv`. Без перетаскивания проверяет
  записи сборок ветвей на этом ПК. Камеры не трогает и может идти рядом
  с приложением.
* `Разбор записи.cmd` — куда смотрел участник: перетащите архив или
  папку с архивами — рядом с архивом появится папка `<имя>_eye` с
  `index.html` (качество взгляда, куда уходило время изучения, походы на
  полку и на карту, «перед нажатием» — что было под взглядом перед
  каждым нажатием по звезде, книге полки и строке найденного, схема
  полки или карты с точками взгляда, «куда смотрели на странице»),
  `fixations.csv`, `visits.csv`, `presses.csv`, `measures.csv` и
  `quality.json`; для
  нескольких архивов — таблица `разбор_записей.csv`. Архив из папки
  «Записи» приложения разбирается в «Документы\Разбор записей
  СНО2026».
* `Сравнение ветвей.cmd` — сводный анализ всех записей: перетащите
  папку с архивами (с обоих ПК и с телефонов, можно по подпапкам) — в
  «Документы\Сравнение ветвей СНО2026\<дата-время>» появятся
  `index.html` (кто вошёл в статистику и с каким весом по шкале лжи,
  какой взгляд дал каждый ПК, нагрузка по ветвям, как искали книги,
  сводка «I против II» и устойчивость вывода), таблицы `участники.csv`,
  `походы.csv`, `ответы_теста.csv`, `сравнение.csv`, `устойчивость.csv`,
  рисунки PNG и SVG и `исходные.json`. `Сравнение ветвей
  (проверочный).cmd` — то же без отсева, все годные архивы с весом 1:
  видно, что работают все части отчёта; не для выводов.
* `Инструкция организатора.txt` — как ставить сборку исследования,
  готовить ПК и телефон, вести сессию и забирать записи.

Ставить ничего не нужно: Python встроен.

## Для разработчика

```bash
python -m pip install --require-hashes --only-binary :all: --no-deps \
  -r requirements.lock -r requirements-dev.lock
python tool/fetch_model.py           # модель по замку (иначе её тесты пропускаются)
python -m pytest -q
python -m sno_eye bench --source synthetic --minutes 0.2 --no-window
```

* `python -m sno_eye serve` — обмен с приложением строками JSON через
  stdin/stdout (SNO-ALG-EYE-03); в записи — `open` с папкой, сегментом и,
  после перезапуска, `calibration` (модель из `calibration.json` без новой
  калибровки), `gaze {on}` — поток взгляда, `check {n}` — проверка в
  конце, `close` — итог `summary.json` (`summary.<сегмент>.json`);
* `python -m sno_eye --selftest` — пробный запуск собранной папки;
* `python -m sno_eye check [архив или папка …] [--json] [--csv путь]
  [--no-csv]` — «Проверка записи» (`sno_eye/record_check.py`, SNO-F-RES-01,
  шаг 33): только стандартная библиотека, пороги — `record_check` в
  `thresholds.json`; код выхода 0 — все годны, 1 — есть с оговорками,
  2 — есть негодные, 3 — проверять нечего;
* `python -m sno_eye report [архив или папка …] [--json] [--out папка]
  [--version raw|drift] [--no-files]` — «Разбор записи»
  (`sno_eye/report/`, SNO-F-RES-03, SNO-ALG-EYE-05, шаг 34): версии
  взгляда (как записано и с поправкой дрейфа по нажатиям мышью),
  фиксации I-DT, зоны по кадрам раскладки «уверенно / на границе», меры
  строго и мягко, походы на полку и на карту, категория на карте —
  группа звёзд с её подписью (BUG-64, правка шага 34), «перед
  нажатием»; только стандартная библиотека,
  пороги — `report` в `thresholds.json`; код выхода 0 — все разобраны,
  2 — есть неразобранные, 3 — разбирать нечего;
* `python -m sno_eye study [папка или архивы …] [--series sno2026-N]
  [--no-filter] [--out папка] [--json]` — «Сравнение ветвей»
  (`sno_eye/study/`, SNO-F-RES-06, шаг 36): приём архивов с подпапками
  (проверка — `record_check`, чтение — `report.archive`), цвет
  искренности по шкале лжи, эталон, шкалы теста нагрузки со сверкой с
  приложением, походы за книгой и меры действий, взвешенное сравнение
  ветвей по ПК (δ Клиффа, бутстреп, перестановки, Холм), шесть
  сценариев устойчивости, рисунки matplotlib; numpy и matplotlib — из
  того же замка, что спутник; пороги — `study` в `thresholds.json`;
  карта скрипта — в шапке `sno_eye/study/__init__.py`; код выхода 0 —
  отчёт готов, 3 — сравнивать нечего, 4 — отчёт не записался.
  Меры взгляда — шаг 37;
* `--source synthetic[:denied|busy|none|dark|noface|slow|twofaces]` —
  синтетика вместо камеры и модели.

Замки: `python_version.txt` (встраиваемый Python), `requirements.lock`
(колёса, `tool/make_lock.py`), `model_version.txt` (модель лица).
Подъём версий — отдельным шагом. Сборку папки делает CI
(`tool/build_windows.py`).
